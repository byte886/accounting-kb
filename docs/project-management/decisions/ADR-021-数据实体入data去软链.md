# ADR-021: 数据实体入项目 `data/高顿`、去掉桌面软链（去 symlink）

> **文档类型**：Active（决策记录）
> **更新频率**：决策变更时
> **维护者**：AI 自动维护 + 用户审核
> **读者**：AI 代理 + 人类

## 状态

已采纳（2026-09-14，用户对 L1 存储迁移方案确认"按方案甲做"：停压缩 → 同卷秒换 → 立即续跑 → 再改配置/文档）。本次只改**本地**数据的存放形态（软链 → 项目内实体目录），不改变 ADR-005 的四地存储分工、ADR-016 的运行时工作区分区、ADR-020 的物理层级与网盘沙箱根名，也不动飞书与百度网盘远端。

## 背景

此前 `data/高顿` 是一个符号链接，指向项目外的 `~/Desktop/高顿`（935G 课程数据实体在桌面），脚本与文档统一经相对路径 `data/高顿/...` 访问。用户希望**不再使用软链、数据实体直接放在项目 `data/` 内，仍由 `.gitignore` 忽略不入库**，理由是项目自包含、换机/克隆归位简单、消除软链带来的额外心智与"find 需带 `-L`、换机要重建链接"等坑。

迁移时后台正在跑视频压缩（compress_ep3_videos.py），另有一个会话窗口在做知识库优化，要求停机时间最短、已压进度不丢。

### 决策依据（迁移前只读勘查得到的三条关键事实）

1. **同卷秒换**：`~/Desktop` 与项目目录在同一块盘、同一个 APFS 卷（设备号相同）。`mv ~/Desktop/高顿 data/高顿` 是同卷 rename（改目录项），秒级完成、**不复制字节、不额外占用空间**，与 935G 体积无关。
2. **忽略规则现成**：`.gitignore` 已整体忽略 `data/`，实体化后数据依旧不入库，无需新增忽略规则。
3. **现役链路对软链无依赖**：cdp 下载、knowledge 知识生成、compress 压缩、网盘 sync、`course_config.COURSE_LOCAL_ROOT` 全部走相对路径 `data/高顿/...`（`code/scripts/cdp`、`code/scripts/knowledge` 下零 `~/Desktop` 绝对引用）。软链换成同名实体目录后该路径字符串不变，主力脚本无感知。压缩脚本幂等：已 hevc 的自动跳过、进度记 `compress_state.jsonl`、中断的 `.compress_tmp__*` 重启自动重压。

## 决策

1. **数据实体化**：删除 `data/高顿` 软链（先 `test -L` 确认是链接才 `unlink`，绝不 `rm -rf` 跟随），将 `~/Desktop/高顿` 同卷 `mv` 为项目内实体目录 `data/高顿/`；此后桌面不再有"高顿"文件夹，数据唯一实体在项目 `data/高顿/`，整体被 `.gitignore` 忽略、不入库。
2. **配置收口**：`code/scripts/course_config.sh` 的 `COURSE_DESKTOP_ROOT` **保留变量名**（转写/编码/结构检查 4 个下游脚本仍引用，避免改名扩散），其值改为等同 `COURSE_LOCAL_ROOT`（`data/高顿/CPA/$COURSE_NAME`），不再指向桌面。
3. **建链脚本退役**：`code/scripts/setup_data_symlink.sh`（专门创建桌面软链）使命消失、且误跑会与实体目录冲突，按精简原则移废纸篓；换机/克隆改为"把课程数据放回 `data/高顿/`（从百度网盘镜像拉回）"，不再建软链。
4. **网盘远端不动**：百度网盘根 `/apps/CPA课程归档/...` 结构与 ADR-020 的沙箱根名约束完全不变，本次纯本地形态调整。
5. **文档与记忆同步**：现行规范/手册/记忆 concept 中"`data/高顿` 是软链 / 指向桌面 / find 需 `-L` / 本地在 `~/Desktop/高顿`"等表述统一改为实体目录口径；ADR-005/016/020 等历史 ADR 与 CHANGELOG 按"编年体只增不改"保留原文，由本 ADR 承接新结论，工程记忆 concept `architecture-storage-layout` 同步修订并在 `memory/log.md` 留痕。

## 迁移与校验记录

- 迁移前基线 = 迁移后实测：**12401 条目 / 10448 文件 / 935G，完全一致（零丢失）**；顶层结构（`CPA/通用做题思路解析.md` + 8 个课程目录）齐全。
- 压缩重启后扫描到 2062 个 `*_video.mp4`（与迁移前一致），自动跳过已 hevc 的 298 个，从审计中断点（86 讲）续压，ffmpeg 输入路径已是新的实体 `data/高顿/...`，断点零重复。

## 后果

**正面**

- 项目自包含：不再依赖项目外的桌面绝对路径，克隆/换机只需把数据放回 `data/高顿/`。
- 消除软链坑：无需换机重建链接、`find data/高顿` 不再需要 `-L`、不会误删软链目标。
- 主力链路零改动：相对路径不变，压缩/下载/生成/同步全程无感知。

**注意 / 配套清理**

- 实体化后项目目录本身体积 ≈ 数据体积（935G），但 `data/` 被 gitignore 忽略，不影响 Git 仓库体积与提交。
- 配套清退 15 个写死 `~/Desktop/高顿` 绝对路径的历史一次性知识详解清洗脚本（`fix_p0/p1/p2_*`、`fix_error*`、`count_long_paragraphs.py`、`assess_remaining.py`，均 0 现役引用、移废纸篓可恢复）；现役可复用工具 `batch_ocr.sh`（被 `ocr/run_ocr_all.sh` 调用）默认值、`watch_stage_done.sh`（通用监听器）示例改为 `data/高顿` 相对路径后保留。
