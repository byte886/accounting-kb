# ADR-007: 静态文档与动态内容分离（docs/ vs project-management/）

> **文档类型**：Active（决策记录）
> **更新频率**：决策变更时
> **维护者**：AI自动维护
> **读者**：AI代理+人类

## 状态

已采纳（2026-08-29）

## 背景

随着项目文档数量增长（40+个md文件），出现以下问题：

1. **docs/目录混合静态和动态内容**：docs/project-management/ 下既有静态的规范文档（standards/、decisions/），也有动态的状态文档（active/、test-plans/），职责边界不清晰。
2. **动态内容频繁更新影响静态文档**：任务状态、问题跟踪等动态内容频繁更新，与静态的规范文档混在一起，增加了维护成本。
3. **reports/目录位置不合理**：任务报告放在项目根目录的 reports/ 下，与项目管理相关的动态内容分散在不同位置。
4. **报告目录名称不清晰**：reports/ 和 verification-reports/ 名称相似，容易混淆，不清楚各自的用途。

## 决策

### 1. 分离静态文档和动态内容

- **docs/**：只放静态内容（方法论、流程、说明、规范、决策记录）
- **project-management/**：放动态内容（任务状态、问题跟踪、测试计划、报告）

### 2. 调整 project-management/ 目录结构

```
project-management/            # 项目管理（动态内容）
├── active/                    # 活动状态（频繁更新）
│   ├── TASK_STATUS.md         # 任务状态
│   ├── ISSUES.md              # 问题跟踪
│   ├── BATCH_TASK_STATUS.md   # 批量任务状态
│   └── COURSE_INDEX.md        # 课程索引
├── test-plans/                # 测试计划（按课程生成）
├── task-reports/              # 任务执行报告（按任务生成，原reports/）
└── verification-reports/      # 质量验证报告（按验证生成）
```

### 3. 明确报告目录的职责边界

- **task-reports/**：任务执行报告，记录任务完成情况、产出物、耗时等
- **verification-reports/**：质量验证报告，记录知识库质量验证、测试验证等结果

### 4. 保留 docs/project-management/ 下的静态内容

- **standards/**：标准规范（静态）
- **decisions/**：决策记录（半静态，只增不改）

## 后果

### 正面
- docs/目录只放静态内容，职责清晰
- project-management/目录放动态内容，以项目管理为名，符合用户建议
- task-reports/和verification-reports/目录名称清晰区分，避免混淆
- 动态内容和静态内容分离，降低维护成本
- 所有引用已更新，验证通过

### 负面
- 移动文件后，所有外部引用（如飞书文档中的链接）需要手动更新（项目内链接已全部更新）
- 团队成员需要适应新的目录结构（已通过README和文档地图说明）

### 后续
- 每次新增重要决策时，按此模板记录到 `docs/project-management/decisions/`
- 定期检查静态文档和动态内容的分离是否合理

## 演进注记（2026-09-08，不改写上方历史原文）

本决策当时把"动态内容"整体放 `project-management/`（active 台账 + task-reports + test-plans）。运行两门课后进一步收敛：

- **`project-management/` 只留两份跨课全局台账**：`TASK_STATUS.md`（进度视图）、`ISSUES.md`（问题视图）；原 `BATCH_TASK_STATUS.md`、`COURSE_INDEX.md`、`STAGE2_EXECUTION_PLAN.md` 等**课程级定格件删除**。
- **单课过程件（含任务报告、批次/工单状态、侦查检查报告、日志断点）全部下沉 `data/_workspace/<course>/`（gitignore、不入库）**；上方目录树中的 `task-reports/`、`verification-reports/` 不再作为仓库持久目录，任务报告改落 `data/_workspace/<course>/task-reports/`，验证结论默认并入任务输出、不单独成文。
- 静态/动态分离的总原则不变，只是"动态"进一步拆成：跨课全局活态（active）vs 单课过程件（workspace，不入库）。现状以 `docs/DIRECTORY_STRUCTURE.md` 与 `project-management/README.md` 为准。
