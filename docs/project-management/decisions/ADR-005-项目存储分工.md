# ADR-005：项目存储分工（GitHub/本地/网盘/飞书）

> 🔁 **【演进 · 2026-09-04】** 四地分工的最新口径（Git 只放工程、本地 data 全量、网盘镜像原始资源+知识详解、飞书只同步知识详解）以 [ADR-012](./ADR-012-三层解耦与按知识点聚合.md) 与 [DIRECTORY_STRUCTURE 第〇章](../../DIRECTORY_STRUCTURE.md) 为准；本 ADR 作为历史决策保留。

## 背景

项目涉及多种类型的内容：代码/脚本、需求文档、工作流、视频文件、讲义文档、文字稿、知识库、任务报告等。不同类型的内容有不同的存储需求，需要选择合适的存储平台。

## 决策

采用四平台存储分工：

| 平台 | 存储内容 | 原因 |
|------|----------|------|
| **GitHub仓库** | Skill代码、需求文档、工作流、项目计划、报告模板、加密凭证、轻量派生/路由元数据（如 lecture-resource-map） | 版本控制、协作、跨设备同步 |
| **本地目录** (`~/Desktop/高顿/`) | 视频文件、讲义文档、文字稿（生成结果） | 大文件、频繁访问、处理中间文件 |
| **百度网盘** (`/apps/CPA课程归档/高顿/`) | 与本地完全镜像的视频和文档 | 备份、跨设备访问、长期保存 |
| **飞书知识库** | 视频文字稿、文档文字、知识梳理 | 搜索、问答、知识管理 |
| **飞书文档** | 任务报告 | 分享、协作、在线查看 |

## 备选方案

| 方案 | 优点 | 缺点 |
|------|------|------|
| 全部放GitHub | 统一管理 | 大文件（视频）不适合Git，仓库会膨胀 |
| 全部放本地 | 简单 | 无备份，跨设备访问困难 |
| 全部放网盘 | 备份好 | 访问慢，不适合频繁修改的文档 |
| 全部放飞书 | 协作好 | 大文件支持差，版本控制弱 |
| **四平台分工** | **各取所长，适合不同内容类型** | **需要维护多平台同步，结构复杂** |

## 决策理由

1. **GitHub适合代码和文档**：版本控制、差异对比、协作、跨设备同步
2. **本地适合大文件和处理中间文件**：视频压缩、音频转写需要快速本地访问
3. **百度网盘适合备份和长期保存**：与本地镜像，防止数据丢失
4. **飞书知识库适合知识管理**：搜索、问答、标签、层级结构
5. **飞书文档适合任务报告**：在线分享、协作、移动端查看
6. **轻量派生元数据入库、大体量原始数据不入库的边界（2026-09-04 补充，对应 ADR-011 第4条修订）**：`lecture-resource-map.json` 这类**体积小（约 24K）、全相对路径无敏感信息、跨环境 clone 即要用、且需要用 git diff 追溯变化**的派生/路由元数据放 GitHub（`knowledge-base/`）；而 papers 题源、cdp-sniff 抓包等**大体量、机器相关、可重新采集**的原始数据仍留本地 `data/` 不入库。判据三问：是否轻量、是否跨环境即需、是否要版本追变——三者皆"是"则入库，否则留 data/。

## 同步原则

1. **GitHub**：文档和代码变更后立即提交
2. **本地→网盘**：视频和文档处理完成后上传百度网盘，保持镜像
3. **本地→飞书知识库**：知识梳理完成后同步到飞书知识库
4. **飞书文档**：任务报告生成后创建飞书文档

## 符号链接

项目目录中的 `data/高顿/` 是符号链接，指向外部数据目录（默认 `~/Desktop/高顿/`）。不同电脑上数据目录路径可能不同，运行 `./code/scripts/setup-data-symlink.sh` 可快速创建或调整符号链接。

> **演进注记（2026-09-07）**：该脚本已按命名规范（脚本一律 snake_case）更名为 `./code/scripts/setup_data_symlink.sh`，旧连字符名 `setup-data-symlink.sh` 已不存在；用法不变（默认路径 / 自定义路径 / `--check` 只检查）。本 ADR 为历史决策记录，原行保留不改，现行脚本名以此注记为准。

> **演进注记（2026-09-14，ADR-021）**：`data/高顿` 已由"指向 `~/Desktop/高顿` 的符号链接"改为**项目内实体目录**（整体 gitignore、去软链）；`setup_data_symlink.sh` 同步退役，换机/克隆改为把课程数据放回 `data/高顿/`（从百度网盘镜像拉回）。本 ADR 为历史记录、原行保留不改，现行存储形态以 [ADR-021](./ADR-021-数据实体入data去软链.md) 与工程记忆 concept `architecture-storage-layout` 为准；四地分工本身不变。
