## 背景

阶段一收尾盘点时发现：39讲中仅17讲 `docs/` 目录有课件PDF，其余22讲 `docs/`、`docs_text/` 为空。若按"每讲一个课件"的直觉判断，会误判为"22讲缺讲义"，并在34章知识库重建时错误地把这些讲标记为"无讲义来源"。

经列出全部28个课件PDF核实，真实结构是：**高顿官方课件按税种模块编号（01–14），一个模块课件覆盖连续多讲，并统一存放在该模块的起始讲目录下**。例如：

- `02增值税`课件放在06讲，覆盖06–12讲；
- `04企业所得税`课件放在19讲，覆盖19–24讲；
- `05个人所得税`课件放在25讲，覆盖25–29讲。

因此"空docs目录"是正常存放结果而非缺失，但这层覆盖关系此前没有落盘，只存在于对话记忆中，不符合"文档是唯一可信记忆来源"原则。

## 决策

1. **确认"一课件覆盖多讲、放模块起始讲"为正常结构**，不视为缺讲义、不重复下载。
2. **建立逐讲原料映射 `knowledge-base/lecture-resource-map.json`**：对39讲中每讲记录「课件来源讲次 + 具体课件PDF相对路径 + OCR文本路径 + 本讲转写路径」；经 `code/scripts/verify_lecture_map.py` 验证 **39讲全部有课件来源、无遗漏**，该脚本可校验映射与磁盘一致性、并按磁盘 `--rebuild` 重建。
3. **34章知识库重建时**，对本讲 `docs/` 为空的讲次，必须按该映射取对应跨讲课件的OCR，**不得判为"无讲义来源"**；映射与 papers（按 chapter 字段匹配讲次）、本讲 transcript 共同构成每讲原料集。
4. **归属与入库（2026-09-04 修订）**：映射是**轻量派生元数据**（约 24K、全相对逻辑路径、无敏感信息、S2 取料必需、换环境 clone 即要用、且官方课件变化时需要追溯差异），故由最初的放 `data/`（不入库）**改为放 `knowledge-base/lecture-resource-map.json` 并纳入 Git 版本化**。官方课件结构变化时跑 `code/scripts/verify_lecture_map.py --rebuild` 刷新并提交，diff 即可看出"哪讲来源变了"。边界：**轻量、需跨环境复用、要追变化的派生元数据入库；大体量/机器相关的原始抓取（papers、cdp-sniff 等）仍按 ADR-005 留 `data/` 不入库**。"讲次→章节如何映射"的通用方法仍属 [chapter-mapping-draft.md](../../development/knowledge/chapter-mapping-draft.md) 方法论，二者不重复。
5. 课件结构若在新课程/新考季变化，以同样方法重新生成映射，不硬编码。

## 后果

### 正面
- 消除"22讲缺讲义"的系统性误判，34章重建原料齐全、可复算。
- 跨讲关系落盘，新会话/其他AI无需重新盘点即可取料。
- 业务数据与方法论分离，符合静态/动态分离（ADR-007）与存储分工（ADR-005）。

### 负面
- 原料来源不是"同目录自取"，生成脚本必须先读映射，多一个间接层。
- 映射依赖课程库目录现状，手工移动/增删课件后需跑 `code/scripts/verify_lecture_map.py --rebuild` 重建并校验（脚本会列出缺失、未登记、旧命名重复件）。

### 后续
- 34章重建（STAGE2_EXECUTION_PLAN S2）以该映射为取料依据。
- 新课程（如会计）开课时复用本机制生成各自映射。
