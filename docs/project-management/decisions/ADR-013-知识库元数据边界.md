# ADR-013: 知识库元数据边界——最终产物只保留纯知识内容，原始资料保留完整字段

> **文档类型**：Active（决策记录）
> **更新频率**：决策变更时
> **维护者**：AI自动维护 + 用户审核
> **读者**：AI代理+人类

## 状态

已采纳（2026-09-07）。本决策由用户两次收紧要求驱动（先移除点赞数、再移除学员名），是知识库内容纯净度的边界规范。

## 背景

用户笔记批量采集（119 份试卷、2323 条原始笔记、288 位用户）后，整理脚本 `organize_user_notes.py` 将笔记写入 92 篇知识详解的「四、学员补充」节。初版输出包含两类元数据：

1. **点赞数标注**：`- 笔记内容（，12 赞）`，共 524 处；
2. **学员名标注**：`- 笔记内容（学员 张三）`，共 745 处。

用户明确指出："点赞数这种没有价值的数据都清理掉了吧"、"学员名这些信息都是没有价值的。千万别形成知识库"。

核心矛盾：**原始资料需要完整字段用于筛选排序和溯源，但最终知识库产物不应包含任何个人信息或无价值元数据。** 两者需要明确分层。

## 决策

### 1. 两层数据的元数据策略

| 数据层 | 位置 | 元数据策略 |
|--------|------|-----------|
| **最终知识库产物**（知识详解） | `data/课程库/<课程>/知识详解/` → 网盘 → 飞书 | **只保留纯知识内容**，不输出学员名、点赞数、用户 ID、日期、noteId 等一切元数据 |
| **原始资料**（用户笔记） | `data/课程库/<课程>/原始资源/user-notes/` + `data/user-notes-raw/<profile.key>/`（按课程 key 隔离） | **保留完整字段**（学员名、点赞数、日期、studentId、noteId），用于筛选排序、溯源、日后重整理 |

### 2. 知识详解「四、学员补充」节的输出规范

- 每条笔记只输出 `- {纯文本内容}`，不附加任何来源标注；
- 节标题「## 四、学员补充」和分类子标题（「### 记忆口诀」「### 易错点辨析」「### 解题技巧」「### 知识补充」）保留——它们是内容分类标签，不含个人信息；
- 整理脚本内部可使用点赞数做 Top-N 筛选，但筛选结果输出时剥离点赞数。

### 3. 脚本根治

- `code/scripts/knowledge/organize_user_notes.py` 已修改：彻底不输出 `studentName` 和 `fabulousNum`，只输出 `noteContent` 纯文本；
- 重新生成时不会再带元数据，无需事后清理。

## 与历史 ADR 的关系

- **补充 ADR-012**：ADR-012 规定了知识详解的四节结构（知识拆解/考试指导/题答解析/学员补充），本决策细化「学员补充」节的内容纯净度边界。
- **不冲突 ADR-005**：原始资料保留完整字段符合 ADR-005「原始资源永久层传网盘」的定位；最终产物剥离元数据是内容层面的规范，不改变存储分工。

## 后果

### 正面
- 知识库无任何个人信息，符合隐私保护要求；
- 无价值元数据（点赞数）不占用阅读注意力；
- 原始资料仍可追溯、可重新筛选排序，不损失信息；
- 脚本已根治，后续课程直接复用不会再犯。

### 负面
- 读者无法知道某条笔记来自哪位学员（但这正是目标——学员名无知识价值）；
- 原始资料与最终产物内容不一致（原始有元数据、产物无），需要明确分层以免混淆——已通过本 ADR 和目录结构固化。

### 后续
- 会计课开工时直接复用本规范，`organize_user_notes.py` 无需修改；
- 如未来新增其他知识来源（如老师答疑、论坛帖子），按同一原则处理：产物只留知识内容，原始资料保留完整字段。
