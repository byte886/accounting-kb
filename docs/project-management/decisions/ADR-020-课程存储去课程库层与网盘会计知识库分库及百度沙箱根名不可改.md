# ADR-020: 课程存储目录去"课程库"中间层、网盘插入"会计知识库"分库层，及百度沙箱根名不可改的约束

> **文档类型**：Active（决策记录）
> **更新频率**：决策变更时
> **维护者**：AI 自动维护 + 用户审核
> **读者**：AI 代理 + 人类

## 状态

已采纳（2026-09-12，用户对 L1 方案确认"本地也去掉课程库层，其它按推荐做"）。本次调整本地与百度网盘的课程物理目录层级，并在网盘顶层按领域分库；不改变 ADR-005 的四地存储分工、ADR-012 的三层解耦，也不动飞书知识库节点层级。

## 背景

用户要求把百度网盘目录由 `CPA课程归档/高顿/CPA/课程库/<课程>` 调整为"顶层改名知识库归档 → 会计知识库 → 高顿 → CPA →（去掉课程库层）→ 各课程"，并确认本地目录同步去掉"课程库"层。调整前云端真实结构为：

```
/apps/CPA课程归档/
├── 高顿/CPA/课程库/<6 个已传课程>
├── 股票知识库
└── 珠宝知识库
```

本地 `data/高顿` 是指向 `~/Desktop/高顿` 的软链，物理课程在 `~/Desktop/高顿/CPA/课程库/<8 个课程目录> + 通用做题思路解析.md`。

### 关键实验结论：百度应用沙箱根目录名与授权绑定、不可通过 API 改名

按用户设想先把顶层 `rename /apps/CPA课程归档 → 知识库归档`，操作返回成功、`list` 读取也正常，但随后在其下 `mkdir` 持续返回 **`31064 file is not authorized`**（等待授权传播后仍复现）；把顶层 `rename` 回 `CPA课程归档` 后，mkdir/delete **立即恢复正常**（探测目录建删成功）。由此确证：开放平台 access_token 的可写范围绑定 `/apps/<应用沙箱根名>`，一旦用 API 改名根目录，token 对新根名即失去写权限（读不拦截、写拦截）。这不是参数或凭证失效问题，是平台机制硬约束。

### 控制台"应用名称"与网盘沙箱物理根是两套、互相脱钩（2026-09-12 只读复核）

用户在开放平台控制台看到应用可"编辑"改名（控制台展示名当时已是"知识归档"），质疑为何网盘目录不能随之改。只读 `list /apps` 复核：网盘 `/apps/` 下**仅有一个物理目录 `CPA课程归档`**（全部数据在内），而按控制台现名 `/apps/知识归档`、按 API 测试名 `/apps/知识库归档` list 均返回 `errno -9 不存在`。结论：

- 控制台"应用名称"只是**展示标签**（控制台列表 / OAuth 授权页显示），可随时编辑，但**不会重命名、也不会重建**网盘里已生成的 `/apps/<根>` 物理目录，更不改 token 的授权路径；
- 网盘沙箱物理根在**应用创建那一刻按当时应用名一次性生成**并与 appkey 的文件写授权 scope 固化（本应用 2026-08-26 创建时名为 CPA课程归档，故物理根与写授权都锁死在 `/apps/CPA课程归档`，与控制台后来改成什么无关）；
- 因此不存在"控制台改个名、网盘顶层根目录安全跟着改且保持写权限"的路径；要让物理根真正叫新名，只能新建应用生成全新空沙箱、换新 appkey/secret 重授权、全量重传并改全部 remoteRoot（等价迁移、非改名）。

## 决策

### 1. 网盘：保留沙箱根名，内部插"会计知识库"层、去"课程库"层
- 物理根 `/apps/CPA课程归档/` **保留原名**（API 改不动；强行改名会废掉全部自动同步写权限）。
- 根内新增领域分库层 `会计知识库/`，把 `高顿/` 整体移入其下；删除 `CPA/课程库/` 中间层，6 个课程直接挂到 `CPA/` 下。最终单课路径：
  - **旧**：`/apps/CPA课程归档/高顿/CPA/课程库/<课程>`
  - **新**：`/apps/CPA课程归档/会计知识库/高顿/CPA/<课程>`
- `股票知识库`、`珠宝知识库` 与 `会计知识库` 平级、原地不动（顶层本就是综合"知识库归档"容器，按领域分库）。
- 云端移动用 xpan `filemanager opera=move`（服务端秒移、不重传、不耗流量）；为此给 `code/scripts/netdisk/baidu_upload.py` 新增 `move <源> <目标父目录> [新名]` 子命令。

### 2. 本地：去掉"课程库"层（data 软链与 Desktop 是同一份，只移一次）
- `~/Desktop/高顿/CPA/课程库/*`（8 个课程目录 + `通用做题思路解析.md`）整体上移到 `~/Desktop/高顿/CPA/`，删除空的 `课程库/`；`data/高顿` 软链自动跟随。
- 跨课通用篇《通用做题思路解析.md》由"课程库层"改称为 **CPA 层**（与各课程目录平级，物理位置 `高顿/CPA/通用做题思路解析.md`）。

### 3. 飞书知识库节点层级本次不动
飞书知识空间「CPA备考知识库」内的 `课程库` 是**浏览层节点**（CPA备考知识库/课程库/各课程/模块组/知识点），与本地、网盘的物理存储层解耦（ADR-005 存储分工）。本次只改物理存储，不删飞书"课程库"节点；模板中飞书导航/层级树（`KNOWLEDGE_BASE_TEMPLATE.md §一/§六`、`DIRECTORY_STRUCTURE.md §四`）保持原样。

### 4. 引用同步口径
- 8 个 `config/courses/*.json` 的 `localRoot`（去课程库）与 `remoteRoot`（插会计知识库、去课程库，根名仍为 CPA课程归档）；`course_config.sh` 三个 ROOT 变量；`ep3_verify_local.js` 的 `path.join` 去掉 `'课程库'` 段；其余 sync/verify 脚本读 config，不硬编码、自动生效。
- 目录树文档（REQUIREMENTS、netdisk-setup、NAMING、README、WORKFLOW）按新结构重画；层级术语"课程库层"统一改"CPA 层"。
- **历史 ADR-005/006/009/013/014 不改写**（保留当时路径原貌）；工程记忆 concept 是"编译层"，更新到最新；memory `log.md` 倒序记一行。
- "课程库"作为**泛称**（指课程成品存储区，如"课程库根不留过程件""扫描课程库"）且不带路径/层级位置的表述，保留不动。

## 后果与边界

- 同步、校验、下载落位脚本经 config/ROOT 统一指向新路径；移动本地目录前必须先停后台下载调度器（否则进程会按旧路径重建 `课程库/`），改完再断点续跑重启——本次已按此顺序执行。
- **用户原始诉求中的"顶层改名知识库归档"未实现**，这是百度平台硬限制，非 AI 自身问题（已有改名即 31064、改回即恢复的硬证据）。若未来坚持要改顶层显示名，只能在百度开发者平台/应用授权层面处理，且会改变沙箱根、需重走授权与全部 remoteRoot，成本高、会中断自动同步，**不推荐**；当前以"根名保留 + 根内按领域分库"达成等价的分类目标。
- 审计/财管云端尚无目录，配置改完后未来首次同步直接落到新路径，无需迁移。
- 本决策只管物理目录层级与路径引用；四地分工、飞书同步、成品范式仍由 ADR-005/012/017/019 等约束。
