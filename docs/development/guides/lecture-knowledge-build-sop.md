## 一、输入与输出

### 1.1 一讲的输入原料（全部在本地，业务数据不入库）

| 原料 | 物理位置 | 定位方式 |
|------|----------|----------|
| 课程库讲目录 | `data/高顿/CPA/<课程名>/NN_官方讲次标题/` | 编号 NN 对应讲次，目录名严格用官方标题 |
| 视频转写 | 讲目录下 `transcript.md` | 老师讲解全文 |
| 官方讲义 | 讲目录下 `docs/`（PDF/PPT） | 最权威来源 |
| 讲义OCR | 讲目录下 `docs_text/*_OCR.md` | 图片型课件的文字稿 |
| 旧知识产物（若有） | 讲目录下旧 `知识拆解.md`、`考试指导.md` | 34章重建时的**复用骨架**（见第三节） |
| 本讲作业题/答/解析 | `data/_workspace/<profile>/papers/<paperId>.json` | 用 1.2 的索引按讲次取 |
| 用户笔记 / 高赞考生留言（若有） | `knowledge-base/source-materials/<课程>/用户笔记精华_*.md`、`解析与用户留言_*.md` | **只取用户留言 / 口诀 / 易错补充**；其中官方解析与 papers 重复、以 papers 为准，采集过程残留忽略（见步骤2第4点） |
| 原料逻辑清单 | `knowledge-base/lecture-resource-map.json` | 键=讲次号"01"…，值=该讲课件/OCR/转写清单与跨讲归属 |

> **路径别名说明**：`lecture-resource-map.json` 里的 `讲NN/...` 是**逻辑别名，不是物理目录**；物理文件在课程库 `NN_官方标题/` 目录下、按文件名匹配。
>
> **跨讲课件（ADR-011）**：高顿官方课件按税种模块编号，一个课件可能覆盖连续多讲。resource-map 的 `课件来源讲次` 标记课件实际归属；因此你可能在 02 讲看到文件名带"03"的课件，这是正常跨讲引用，**不是缺讲义**，不要重复生成、也不要判为缺失。映射机制见 `docs/project-management/decisions/ADR-011-讲次课件跨讲映射机制.md`。

### 1.2 取本讲全部 paperId（权威入口：paper_index）

`data/_workspace/<profile>/manifest/paper_index.json` 是 list，每条 `{paperId, title, chapter, cls, qCount, file}`，其中 **`chapter` 字段就是官方讲次标题**。按 chapter 过滤即得一讲全部卷子：

```bash
python3 - <<'PY'
import json
idx=json.load(open('data/_workspace/<profile>/manifest/paper_index.json'))
CH='税法全面精讲01-税法总论'          # 换成当前讲次官方标题
rows=[r for r in idx if r['chapter'].strip()==CH]
for r in rows: print(r['paperId'], r['cls'], r['qCount'], r['title'])
print('共', len(rows), '套', sum(r['qCount'] for r in rows), '题')
PY
```

### 1.3 输出（本地三文件，本地是飞书源头）

```
knowledge-base/organized-content/_34chapters/讲NN/
├── README.md        # 父节点：子节点链接+概述+重点+学习建议+题库验证
├── 知识拆解.md       # 知识本身（客观、结构化）
└── 考试指导.md       # 应试（考情/高频/易错/真题/口诀/建议）
```

- 目录名用 `讲NN`（两位补零），三个文件名固定为中文，与飞书三节点一一对应。
- **先在本地生成并自检通过，再按 WORKFLOW 步骤8 同步飞书；禁止直接在飞书编辑。**

## 二、生成路径判断（先判断走哪条路）

| 情形 | 判断依据 | 加工路径 |
|------|----------|----------|
| **首次从零生成** | 讲目录下没有旧 `知识拆解.md/考试指导.md` | 以讲义OCR+转写为主干搭建，题答补遗漏（sources 3.3） |
| **34章重建（当前主场景）** | 讲目录下已有初始知识库产物（线A骨架，质量通常较好） | **旧骨架复用 + 多源核对 + 题答校验增强**（本 SOP 主线，见第四节） |

> 34章重建**不是推倒重写、也不是照抄旧版**：旧产物已消化过转写与OCR、结构完整，应以它为底座；价值增量来自用本讲全部作业的**官方解析逐题交叉校验**、补真题暴露的细节、并对齐最新来源口径（剔除AI错题）。

## 三、作业步骤

### 步骤0　定位原料、确认不缺料

1. 按 1.1/1.2 列清本讲：转写、讲义/OCR（含跨讲来源）、旧产物、N套卷子M道题。
2. **先跑课件映射校验**：`python3 code/scripts/verify_lecture_map.py` 必须退出 0（legacy=0、无 missing/unlisted）；若报 legacy（旧命名件）或缺失，先按 standards 2.2 去重/补料，校验不过不进入生成。
3. 对照 WORKFLOW「每讲流程检查清单」确认原料状态；原料缺失先补原料，不带着缺口生成。
4. 若有多份疑似重复件（同一课件的旧命名 + 标准命名 PDF/OCR），按 standards 2.2.6 取证：PDF 比 md5、OCR 去标题行后做内容 diff（标准件等同或更优才删旧件，移废纸篓不硬删），重复只取一份，不必全文重读。

### 步骤1　题答盘点：用脚本算出"真实考点分布 + 逐题速览"

**不要凭感觉标高频。** 遍历本讲 papers，按 `knowledgePointList[].title` 聚合题量得到客观考频，并速览每题题型/答案/官方解析要点：

```bash
python3 - <<'PY'
import json,re,html,collections
ids=['82174','82175']   # 换成步骤1.2取到的本讲 paperId
def clean(s):
    s=re.sub(r'<[^>]+>',' ',str(s or '')); return re.sub(r'\s+',' ',html.unescape(s)).strip()
kp=collections.Counter()
for pid in ids:
    d=json.load(open(f'data/_workspace/<profile>/papers/{pid}.json'))
    for m in d['moduleList']:
        for q in m.get('questionList',[]):
            kp.update(k['title'] for k in q.get('knowledgePointList',[]))
            print(f"[{q.get('questionType')}|{clean(q.get('answer'))[:10]}] {clean(q.get('title'))[:42]}")
            print('   ↳', clean(q.get('analysisText'))[:95])
print('\n考点题量分布:', dict(kp.most_common()))
PY
```

`papers/<id>.json` 题目字段速查：题目在 `moduleList[].questionList[]`；题面 `title`(HTML)、选项 `selectList[].optionContent`、标准答案 `answer`（多选形如 "A,B,D"）、官方解析 `analysis`(HTML)/`analysisText`(纯文本)、考点 `knowledgePointList[].title`、题型 `questionType`（1单选/2多选/3判断/5·6主观）。

产出两个内部结论，供后续两步使用：
- **考点题量分布** → 考试指导"高频考点"排序与星级的客观依据；
- **逐题解析要点** → 知识拆解校验清单（哪些点旧骨架没讲清、哪些是真题补充细节）。

### 步骤2　读旧骨架与多源原料

1. 通读旧 `知识拆解.md`、旧 `考试指导.md`，判断结构是否完整、可复用程度。
2. 旧骨架已覆盖且与讲义一致的内容直接保留；只在需要处回看 OCR/转写核对，不必把上百页 OCR 全文重读一遍。
3. 来源严格按 sources：知识拆解只取客观知识（讲义/转写/OCR + 题答暴露的遗漏点），**不写入口诀/易错/真题**；考试指导取考点、易错、真题、口诀；**AI错题、考点图谱一律不用**。
4. `解析与用户留言_*.md` 是旧 UI 时代逐题合集：其中**官方解析已被 papers 的 `analysis/analysisText` 覆盖，直接用 papers、不重复读**；只提炼「用户留言 / 高价值口诀 / 易错补充」（papers 不含、是独有增量），并忽略文末"交互流程优化总结 / 收集效率"等采集过程残留。该类原始 md 在**本讲三件套生成、且确认留言已提炼进成品后**才完成使命，按 standards 2.2 作为 L4 取证原料清理（结论已入成品、可追溯），**此前保留、不提前删**。

### 步骤3　生成 `知识拆解.md`（旧骨架增强）

1. 沿用旧骨架的章节组织，**按知识点而非视频时间线**；结构规范遵循 organization（Answer-First、原子化、严格层级、MECE、关键对比用表格）。
2. 用步骤1的逐题解析**逐点校验**：
   - 旧骨架正确 → 保留；
   - 题目暴露而旧骨架缺失的客观细节 → 补入，并在该点行内用 **`（真题补充：…）`** 标注，便于追溯这是由题答校验补出的点；
   - 旧骨架与官方解析/讲义冲突 → 以讲义>官方解析为准修正，并在任务记录里说明；
   - 不臆造：拿不准且原料无据的，标"待确认"，不写成定论。
3. 头部 Context Block 用精确来源写法（见第六节），并写"题库验证结果"块（验证题数、考点分布、补X处、错X处、结论）。
4. 末尾注明配套考试指导互链。知识拆解中**不得出现**真题回顾、易错点、记忆口诀等应试内容。

### 步骤4　生成 `考试指导.md`（用题量定高频）

按 organization 固定顺序：**考情分析 → 高频考点 → 易错点辨析 → 记忆口诀 → 历年真题回顾 → 学习建议**。
- 考情：章节定位、题型、分值、学习策略；用步骤1的**考点题量分布表**呈现真实高频度（可标★），不凭空标重点。
- 高频/易错：从官方解析提炼；易错点用"❌错误表述 → ✅正确表述"对照。
- 真题回顾：优先取本讲分章真题卷中带年份的历年真题，给题干、选项、答案、一句解析；题量多时选代表性题、覆盖各高频考点。
- 口诀：来自转写/讲义或用户笔记（用户笔记标注来源、冲突以讲义为准）。
- 头部同样写精确来源与配套知识拆解互链。

### 步骤5　生成父节点 `README.md`

按模板第四级章节节点：标题=官方讲次标题；含①两个子节点可点击链接+一句说明 ②章节概述 ③重点内容(3–7条) ④学习建议 ⑤**题库验证**（N套M题、满分情况、考点分布、校验结论）。父节点只做目录与导航，不承载正文知识。

### 步骤6　单讲自检（不过不进入下一步）

- [ ] 三文件齐全，文件名/目录名符合 1.3；标题严格等于官方讲次标题。
- [ ] 内部相对链接全部有效、知识拆解↔考试指导双向互链、README 两个子链接可达。
- [ ] 来源口径正确：未混入 AI 错题、考点图谱；用户笔记仅入考试指导且冲突从讲义。
- [ ] 知识拆解"纯净"：无考点提示/易错/口诀/真题；应试内容全在考试指导。
- [ ] 题答校验闭环：考点分布由脚本算出、补充点有"真题补充"标注、验证结果块数字与 paper_index 对得上（N套M题一致）。
- [ ] 关键事实（税率、级次、收入划分、年份数字）与讲义/官方解析一致，无臆造。
- [ ] 层级不跳级、表格可正常渲染。

链接自检可用：

```bash
D=knowledge-base/organized-content/_34chapters/讲NN
for f in "$D"/*.md; do d=$(dirname "$f"); grep -oE '\]\(([^)h][^)]*\.md)\)' "$f" | sed 's/](//;s/)//' | while read l; do [ -f "$d/$l" ] && echo "OK $l" || echo "断链 $l"; done; done
```

### 步骤7　衔接下游与产物去向（不在本 SOP 内展开）

1. **网盘备份**：按 WORKFLOW 步骤6，原料（压缩视频/转写/讲义）在做题后、知识生成前一次性上传到该讲网盘目录；本讲两个知识 md 生成后对该讲重跑上传脚本补传（已存在文件 MD5 秒传）。**papers 题答不进讲目录**，按 standards 2.2.4 集中备份到网盘"知识原料区"。
2. **飞书同步**：本地三文件自检通过后，按 WORKFLOW 步骤8 用 lark-cli 同步到对应讲次节点并回读；旧15章节点按"新34讲核对无误后逐章替换"处理，不提前删旧节点。
3. **产物去向与清理（判据见 standards 2.2，此处只对号入座、不复制规则）**：
   - L1 底片：`papers/`、讲义 PDF、`transcript.json` —— 本地留、网盘备份、不入库；
   - L2 成品：`video.mp4`、`transcript.md`、`*_OCR.md`、本讲三个 md、飞书节点 —— 最终交付，本地 + 网盘 + 飞书；
   - L3 续跑/路由：`.vfetch/`、papers_inventory/audit 阶段中保留，整条线定稿后清；`lecture-resource-map.json` 属轻量派生元数据，入库版本化；
   - L4 一次性取证：侦查 JSON/截图/PoC 输出，结论入文档即清；清理一律移废纸篓，不硬删。

## 四、样板先行与批量规则

1. **样板确认门**：每个课程/每个新结构的**第一讲**完整做完后，先交付用户确认范式（结构、颗粒度、风格、来源标注），确认后再按同一范式批量其余讲，避免34讲做完才发现系统性偏差。
2. **批量一致性**：后续讲严格复用本 SOP 与确认后的样板，结构、头部字段、标注约定、自检口径保持统一。
3. **一讲一闭环**：每讲走完步骤0–6即为本地完成；批量时逐讲记录状态（见该课 `data/_workspace/<course>/` 的工单与 manifest，讲次清单以官方 syllabus 为准），并可与网盘上传等 IO 任务并行调度（并发原则见 WORKFLOW「多任务并发调度」）。
4. **跨讲不重复**：课件跨讲时（ADR-011），知识内容在课件归属讲组织，引用讲只做指引，不复制粘贴造成重复与不一致。

## 五、常见坑

| 坑 | 正确做法 |
|----|----------|
| 把 resource-map 的 `讲NN/` 当物理目录去找文件 | 它是逻辑别名，物理文件在课程库 `NN_官方标题/` 下 |
| 看到 02 讲课件文件名带"03"以为缺讲义 | 跨讲课件正常现象，查 resource-map `课件来源讲次` 与 ADR-011 |
| 凭经验/感觉标"高频考点★★★" | 必须用 paper_index+papers 脚本聚合 knowledgePoint 题量定高频 |
| 把旧 Playwright AI 错题、考点图谱当来源补进知识库 | sources 已明确否决，禁止使用 |
| 知识拆解里写真题/口诀/易错 | 双文档分离，这些只进考试指导 |
| 照抄旧版不校验，或推倒重写丢掉好骨架 | 走"旧骨架复用+题答校验增强"，补充点用"真题补充"标注 |
| 头部来源仍写"用户留言精华/第X轮迭代"等旧口径 | 用第六节统一精确写法 |
| 本地没自检就同步飞书 | 先过步骤6自检，再按步骤8同步并回读 |
| 用 chapter_structure.json 聚合 papers（其 papers 字段为空） | 一律用 paper_index.json / papers/*.json |

## 六、统一来源头（Context Block）写法

知识拆解 / 考试指导头部统一写成可核对的精确来源（替换占位）：

```
> 课程：2026 CPA 税法-全面精讲 | 主讲：蔡俊峻老师
> 官方讲次：税法全面精讲NN-官方标题（严格对齐官方标题与顺序）
> 整理来源：官方讲义OCR（N页课件）+ 视频转写 + 本讲K套作业M题官方解析（课后X题 + 分章真题Y题，全部满分/平台最优）
> 适用范围：2026考季CPA税法备考
> 生成时间：YYYY-MM-DD（34章重建版，经M题官方解析交叉校验）
> 文档类型：知识本身（结构化知识点）/ 考试指导（考点、易错、真题、口诀）
> 配套文档：[考试指导.md](考试指导.md) / [知识拆解.md](知识拆解.md)
```

> 不写"用户留言精华（N条高赞）"作为并列来源；用户笔记仅在确有素材时于考试指导内单列并标注。不写"第X轮迭代"——本流程是集齐来源一次性生成。
