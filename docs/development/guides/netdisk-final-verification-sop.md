# 课程 finalize 终态检查 SOP（网盘 + 本地 + 飞书）

> **目的**：课程知识系统 finalize 后，验证百度网盘、本地目录、飞书知识库三地完全一致，并清理临时文件和无价值元数据，确保无遗漏、无冗余、无敏感信息残留。
> **适用场景**：每门课程 finalize 后、大规模同步后、定期巡检。
> **工具**：`code/scripts/verify_netdisk_final.py`（网盘自动化递归对比）、`wiki-link-verification-sop.md`（飞书链接验证）。

## 一、检查时机

| 时机 | 说明 |
|------|------|
| 课程 finalize 后 | 知识详解生成 + 三地同步完成后，必须执行 |
| 大规模同步后 | 批量上传/删除/覆盖后，执行验证 |
| 定期巡检 | 每月一次，确认网盘状态未被意外修改 |

## 二、网盘验证

### 2.1 自动化验证（推荐）

```bash
cd <仓库根>
export BAIDU_ENC_PASS=<密码>
python3 code/scripts/verify_netdisk_final.py <本地课程根> <网盘课程根>
```

**示例（税法课）**：
```bash
export BAIDU_ENC_PASS=<主密码>
python3 code/scripts/verify_netdisk_final.py \
    "data/高顿/CPA/【26考季】VIPCPA系列-税法（蔡俊峻老师）" \
    "/apps/CPA课程归档/会计知识库/高顿/CPA/【26考季】VIPCPA系列-税法（蔡俊峻老师）"
```

**脚本功能**：递归扫描本地和网盘目录，对比目录结构、文件集合、文件大小，输出差异清单和修复建议。

**退出码**：`0` = 通过，`1` = 发现差异，`2` = 参数或环境错误。

分类汇总多份核验日志：`python3 code/scripts/netdisk_verify_summary.py <核验日志...>`（讲义缺/不一致、视频缺、视频大小不一致、其中"网盘旧大版"、缺讲目录、垃圾分片）。

#### 2.1.1 hevc 覆盖 h264 场景的核验要点（2026-09-16，ADR-022）

名师课视频由 h264 重压为 hevc 后整科覆盖网盘旧件（门控见 [finalize-sop.md](finalize-sop.md) 步骤 1），此场景核验有三个特殊点：

1. **不信 done，只认核验**：`netdisk_done/*.done` 只证明某次上传动作完成，不证明网盘当前就是 hevc。早期传过 h264 的科目（会计/税法/经济法/财管等）即使有 done，也必须重跑本核验。
2. **网盘不能 ffprobe，靠字节大小判旧版**：hevc 显著小于同内容 h264（实测样本约 1/13）。核验输出里"**大小不一致且网盘文件更大（旧大版）**"即网盘残留 h264，需按 finalize-sop 步骤 1 第 2 条清该科视频 done（保留 `notes__`）后 `rtype=3` 重传，再核验到 rc=0；"网盘更小/缺失"则是漏传，按 6.1 补传。
3. **双机各自核验**：目标机压完上传的会计/财管，在目标机用其本地 `.secrets` 凭证跑核验；hevc 成品 rsync 回传本机后，本机主存储以 hevc 为准。已验证基线：审计 257 讲、战略 129 讲全 hevc 上云，2026-09-16 核验 rc=0、视频 0 缺 / 0 大小不一致 / 0 旧大版、讲义 0 差异。

### 2.2 手动 fallback

脚本不可用时，逐层执行 `python3 code/scripts/baidu_upload.py list <目录>`，与本地 `find`/`ls` 结果对比顶层结构、文件计数、大小抽样。

## 三、本地临时文件清理

finalize 后必须检查并清理本地临时文件，**清理前必须先列清单**（见第五节）。

### 3.1 常见可清理项

| 路径 | 类型 | 说明 |
|------|------|------|
| `logs/parallel_test/` | 并发度测试临时文件 | 测试结果入文档后，可删 `audio.wav` 等大文件，保留 `.log` 和 `transcript.md/json` 作为证据 |
| `logs/<一次性测试目录>/` | 临时测试输出 | 确认结果已记录后可删 |
| `data/.DS_Store` | macOS 系统文件 | 可删 |
| `code/scripts/_tmp_*.sh` / `_tmp_*.js` | 一次性临时脚本 | 执行完毕后可删 |
| `/tmp/upload*.sh` / `/tmp/run_*.sh` | 一次性临时脚本 | 执行完毕后可删 |

### 3.2 需保留项（不可删）

| 路径 | 说明 |
|------|------|
| `data/高顿/` | 课程原料实体目录（ADR-021 去软链，整体 gitignore），保留 |
| `data/_workspace/<profile>/notes-raw/` | 用户笔记原始数据源（按课程 profile key 隔离），保留 |
| `data/_workspace/_account/auth/` | 账号级 JWT 鉴权抓包（跨课共享、滚动留最新），见 3.3 保留策略 |
| `data/_workspace/<profile>/sniff/` | 课程抓包/侦查件（可能含 token），见 3.3 保留策略 |
| `logs/wiki_done/` | 飞书同步断点，保留 |
| `logs/wiki_node_map.tsv` | 飞书节点映射，保留 |

### 3.3 敏感信息保留策略（工作区鉴权与抓包）

鉴权 JWT 在 `data/_workspace/_account/auth/`（账号级、跨课共享），课程抓包侦查件在 `data/_workspace/<profile>/sniff/`（可能含高顿 API 报文与 token，约 7 天有效期）：

- **JWT 过期后**：可删除 `_account/auth/` 含过期 token 的旧抓包文件（滚动留最新）
- **课程相关抓包**：每门课 finalize 后，保留该课关键 ID 抓包（courseId/syllabusId/gradationId 等），删除中间探索性抓包
- **禁止入库/入网盘**：整个 `data/_workspace/` 已被 gitignore 且网盘排除，鉴权与抓包永远不 commit、不上传
- **清理前必须列清单**，确认哪些是关键抓包、哪些是探索性文件；删除一律 `mv` 带时间戳回收站，不硬删

## 四、飞书终态检查

### 4.1 节点完整性

验证飞书知识库节点结构与本地 `知识详解/` 同构：

| 检查项 | 方法 | 通过标准 |
|--------|------|----------|
| 节点数量 | `lark-cli wiki +node-list` 逐层计数 | 课程根→组父节点→知识点子页面+全局篇，数量与本地一致 |
| 节点层级 | 对比 `logs/wiki_node_map.tsv` 的 parent 关系 | 无错挂、无孤立节点 |
| 空节点/重复节点 | 回读各节点正文，检查是否为空或重复 | 0 个空节点、0 个重复节点 |
| 失效节点 | 检查是否有旧版归档节点、已被新结构取代的节点 | 0 个失效节点（或已列清单待删除） |

### 4.2 链接验证

**不重复写**，直接执行 [`wiki-link-verification-sop.md`](wiki-link-verification-sop.md)：

- 三层链接验证：课程总览页 → 章 README → 知识点详解
- 验证所有内部链接指向正确节点、且为 `<cite>` 内部引用（doc-id=obj 可回读校验；正文点击统一新开标签、单窗口连续阅读走左侧知识库目录树），无死链、无错链、无占位符坏链
- 税法课参考值：762 链接（总览页 16 + 章 README 92 + 知识点 654）

### 4.3 元数据清理（无价值数据不得进知识库）

检查知识详解中是否残留以下无价值元数据，发现即清理：

| 无价值数据 | 说明 | 清理方式 |
|-----------|------|----------|
| 学员名（`（学员 XXX）`） | 个人信息，无知识价值 | 本地 md 中删除标注，重新同步飞书 |
| 点赞数/浏览数/收藏数 | 平台互动数据，无知识价值 | 不采集、不写入知识详解 |
| 题目"点拨"节内容混入答案 | 点拨是解析提示，不是标准答案 | 答案只写标准答案，点拨归入解析节 |
| 空分类标题（如"计算/综合大题（0道）"） | 题量为0的分类不应渲染标题 | 本地根治（render_point_qa.py 已有 `if groups:` 保护），重生成后同步 |

**原则**：知识库只存知识本身，不存平台元数据、个人信息、互动数据。

### 4.4 失效节点删除

发现旧版归档节点或已被新结构取代的节点时，按以下流程删除：

1. **列清单**：用 `wiki +node-list` 列出待删除节点的标题、node_token、子节点数量
2. **确认**：用户明确授权后执行
3. **执行**：`lark-cli wiki +node-delete --node-token <token> --include-children=true --yes`
4. **验证**：删除后重新 `node-list` 确认节点已消失，台账 `wiki_node_map.tsv` 同步移除

> 飞书节点删除是**不可逆操作**（不进回收站），必须严格遵循第五节删除规范。

## 五、删除操作规范（强制）

**所有删除操作必须遵循三步流程，禁止直接执行删除命令：**

1. **列清单**：先用 `ls`/`find`/`du` 列出待删除项的名称、大小、数量，输出给用户
2. **确认**：用户明确说"执行"、"清理"、"删除"后才执行
3. **执行**：本地文件 `mv` 到废纸篓（带时间戳），不硬删；网盘文件 `delete` 进回收站（可恢复）

**例外**：用户明确说"优化好了不用找用户确认"或"全部按推荐执行"时，可跳过第2步，但第1步列清单仍然必须执行。

## 六、常见差异与修复

| 差异类型 | 原因 | 修复方法 |
|----------|------|----------|
| 文件缺失-网盘 | 同步时遗漏（如 transcript.json） | 补上传：`baidu_upload.py upload <本地> <网盘>` |
| 文件多余-网盘 | 早期 rtype=1 重命名产生的旧文件（带时间戳） | 删除：`baidu_upload.py delete <网盘路径>`（进回收站） |
| 大小不一致 | 上传不完整或换行符差异 | 重新覆盖上传（rtype=3） |
| 目录缺失/多余 | 目录结构约定变更 | 按约定创建/删除目录 |

### 6.1 批量补上传示例

```bash
find <本地videos> -name "transcript.json" | while read f; do
    rel="${f#<本地videos>/}"
    python3 code/scripts/baidu_upload.py upload "$f" "<网盘videos>/$rel"
done
```

## 七、回收站说明

- 百度网盘 `delete` 操作**进回收站**，可恢复，非硬删除。
- **回收站清空**：当前 OAuth 沙箱 token 无法调用 `recyclelist`/`cleanrecycle` API（返回 500/31296），需账号主人在网盘客户端手动清空，或等 10 天自动到期。
- **不要**用 API 重试清空回收站（已验证死路）。

## 八、通过标准

1. `verify_netdisk_final.py` 退出码为 0，输出 `✅ 验证通过：本地与网盘完全一致`
2. 目录数、文件数本地 = 网盘，无大小不一致的文件
3. 本地临时文件已按第三节清理（列清单后执行）
4. 无残留的一次性临时脚本（`_tmp_*`、`/tmp/*.sh`）
5. 飞书节点完整性：节点数量/层级与本地一致，0 空节点、0 重复节点、0 失效节点
6. 飞书链接验证：执行 `wiki-link-verification-sop.md`，三层合计 0 错误、0 警告
7. 飞书元数据：无学员名、点赞数等无价值数据残留，无空分类标题

## 九、检查留痕

- 检查结论体现在任务输出或《任务报告》中，**默认不单独成文**。
- 若发现差异并修复，修复过程记录在任务报告中。
- 验证脚本本身（`verify_netdisk_final.py`）入库，作为可复用工具。
