## 二、加工程序

### 步骤 0　前置门确认



* 阶段①资源齐、阶段② manifest 归组脚本 assert 通过（92 / 各组点数）；不带缺口生成。

### 步骤 1　题答盘点（脚本算，不凭感觉）

按**知识点**（不是按讲）聚合题量并速览每题，作为 "高频排序 + 知识校验清单"：



```
import json,re,html,collections,glob

def clean(s):

&#x20;   s=re.sub(r'<\[^>]+>',' ',str(s or ''));return re.sub(r'\s+',' ',html.unescape(s)).strip()

kp=collections.Counter()

for fp in glob.glob('\data/_workspace/<profile>/papers/\*.json'):

&#x20;   d=json.load(open(fp,encoding='utf-8'))

&#x20;   for m in d\['moduleList']:

&#x20;       for q in m.get('questionList',\[]):

&#x20;           for k in q.get('knowledgePointList',\[]): kp\[k\['title']]+=1

&#x20;           # 主观题下钻小问

&#x20;           for s in q.get('subQuestionList',\[]) or \[]:

&#x20;               for k in s.get('knowledgePointList',\[]): kp\[k\['title']]+=1

&#x20;           print(f"\[{q.get('questionType')}|{clean(q.get('answer'))\[:10]}] {clean(q.get('title'))\[:42]} -> {clean(q.get('analysisText'))\[:90]}")

print(kp.most\_common())
```

产出：每知识点题量（定高频）、逐题解析要点（校验知识是否遗漏）。

### 步骤 2　建 14 组骨架



* 按 manifest 的显式映射建 `知识详解/NN_组/` 目录；

* 92 个知识点逐一对到组，脚本断言无未归类 / 无重复、总数 92；**不新建 AI 自造组、不改官方点名**。

### 步骤 3　逐知识点生成一篇（固定 4 节）

以**知识点为索引跨讲聚合**（同一点在多讲 / 多卷出现要合并，不按视频时间线）：



1. **一、知识拆解**：以讲义 OCR + 转写为主干（**名师课(ep3)必须同时纳入来源 1d 的 zip 补遗**：`原始资源/notes/<阶段>/` 下「其他_」前缀的第二位老师讲义/课件、以及思维导图 OCR 合并稿（如税法高蒙《思维导图_OCR.md》），不得只用默认老师旧讲义；清单与落位见 [knowledge-base-sources.md §1.2](../knowledge/knowledge-base-sources.md)。迁移期可复用旧成品骨架），按子主题组织，遵循 Answer-First / 原子化 / 严格层级 / MECE；用步骤 1 逐题校验 —— 旧骨架对则保留、题答暴露的缺失点补入并在行内标 `（真题补充：…）`、与讲义 / 官方解析冲突则按 "讲义＞官方解析＞高赞笔记" 修正；拿不准标 "待确认"，不臆造。**本节只放客观知识，不写考点 / 口诀 / 真题。**

2. **二、考试指导**：考情与高频（用步骤 1 题量，不凭经验标星）、易错点（❌错误→✅正确）、记忆口诀 / 技巧（来自转写 / 讲义，学员口诀标注来源）。

3. **三、题答解析（脚本渲染、不手抄）**：收本知识点**全部**题，但不由 AI 转抄——`render_point_qa.py <步骤1聚合JSON>` 机械生成第三节（客观题逐题；主观题按大题 bigStem 分组、下钻小问 (1)(n)，答案/算式取小问 analysisText，每题标来源卷与 paperId）；AI 只校核、不改题面/答案/算式，**剔除自动化 AI 错题**。**计算大题以"大题"为不可拆单位全收、不折叠**，靠 `#### 大题N` 导航。公式/规则放第一节、具体算式放第三节，不重复堆叠。

4. **四、学员补充**：从 notes-raw 提炼高价值讨论 / 助记 / 易错补充（去掉点赞数、采集过程残留）；**无内容则整节省略**。冲突不覆盖正文，按 sources 权威度处理。notes-raw 的 `notes_by_knowledge_point.json` 由 `collect_user_notes.js`（采集）→ `build_notes_mapping.py`（映射到本篇、剥身份字段）生成，聚合卷/近义名走 `notes-raw/alias.json`，勿手工拼中间件（链路见 code/scripts/README「用户笔记子链」）。

5. **拼接成篇**：AI 写"头部"（Context Block ＋ 一、知识拆解 ＋ 二、考试指导 ＋ `## 三、题答解析` 标题），再与 render 产物、`## 关联知识点`（位于三、题答解析之后、四、学员补充之前；同组兄弟篇相对链接，未生成可先挂前向链接）、`## 四、学员补充` 拼接为最终 .md；头部与题答分离，避免 AI 转抄算式出错。

篇首 Context Block：所属组、来源（讲义 a 份 / 转写 b 讲 / 题 c 道）、适用考季、更新时间。

### 步骤 4　课程全局篇



* `课程做题思路解析.md`：结合**本科目**题型的做题套路；

* `考试指导速查手册.md`：只汇总**通用**税率 / 公式 / 对比 / 易错 / 应试技巧与考前通用清单，**不含具体指定业务的题目或场景**；冲刺模考采集后做最终更新；AI 横向提炼处标注 "AI 总结"。

### 步骤 5　组父节点（目录页）

按模板第四节写：组信息块、**全部子知识点页面链接 + 一句摘要**、本组主线、重点、学习建议；只做目录不写正文。

### 步骤 6　样板门与批量（两道样板门，两类题型都验证后才批量）

* **为什么是两道**：14 组中 01 等 10 组为纯客观记忆类，而 03/04/08/12 四组含主观计算大题（questionType=5 容器、6 小问，共数百小问）。只做纯客观样板验证不到"大题→小问、算式分步"分支，故设 A、B 两道样板门分别覆盖两类题型，两道都过才批量。

* **样板门 A（客观概念类）**：取**点数最少的纯客观组**（01_税法总论，6 篇）整组做完，交用户确认客观题范式（颗粒度 / 风格 / 来源标注 / 四节配比）。

* **样板门 B（主观计算类）**：另取**一个含 type5/6 计算大题、规模适中的知识点**做单篇（建议 03 消费税法「生产销售环节应纳消费税的计算」；不选 04 企税"应纳税额的计算"这类上百小问的超大点，避免把"验证范式"和"超大篇幅如何组织"两个问题搅在一起）。样板 B 专门定稿三件事：①大题题干 →(1)(n)小问的固定层级，答案 / 算式取小问 analysisText（小问 answer 常为"见解析"）；②公式 / 步骤放"一、知识拆解"、算式过程放"三、题答解析"的分工；③单个知识点题量过大时的组织策略——**实测结论：计算大题以"大题"为不可拆单位全收、不折叠、不做"典型题＋索引"，靠 `#### 大题N` 导航**（每道大题是完整业务情境，且题答由脚本机械渲染、题量不增加出错成本）。

* **批量条件**：A、B 两道样板门均经用户确认后，再按完全一致的结构、头部字段、标注约定、自检口径批量其余组；批量时可与阶段①遗留 IO 任务并行调度。

## 三、多智能体协作生成流程（生成→检查→整改→循环）

> **为什么用多智能体**：生成和检查分离，避免"自己写自己查"的盲区。生成智能体重在按SOP产出，检查智能体重在挑毛病，两者视角不同，质量更高。

### 3.1 角色分工

| 角色 | 职责 | 输入 | 输出 |
|------|------|------|------|
| **生成智能体** | 按写作风格指南生成一篇/一章 | 知识点原料 + SOP + 风格指南 | 一篇完整的知识点md |
| **检查智能体** | 按质量标准审核，出问题清单 | 生成智能体产出的md | 审核报告（问题列表+整改建议） |
| **总协调** | 决定通过/打回，安排下一章 | 检查报告 | 下一步指令（通过/打回重写） |

### 3.2 工作循环

**逐章循环，不跳着做**：
```
生成智能体写一章 → 检查智能体审一章
  ↓
  ├─ 通过 → 进入下一章
  └─ 不通过 → 打回生成智能体重写 → 再检查
       ↑________________________|
```

**规则**：
- 一个课程完整结束后，立刻做深度质量审核，**不跳着做、不往后拖**
- 同一章打回不超过2次：第2次还不通过，总协调介入分析是范式问题还是执行问题
- 单章审核通过后，再生成下一章——不要批量生成完再统一检查

### 3.3 检查智能体的检查项

按写作风格指南§六（质量审核标准）的6维度打分，任一维度低于3分即打回。

## 四、内容深度质量审核标准（生成后必做）

> 全量自检（§五）是**格式检查**（篇数、题数、链接），本节是**内容深度审核**（好不好懂、专不专业、重不重叠）。

### 4.1 审核维度（6项，每项1-5分）

| 维度 | 评分标准 | 满分线 |
|------|---------|--------|
| 1. 结构清晰度 | 四节结构完整、H2/H3层级分明、逻辑顺畅 | 4分 |
| 2. 语言可读性 | 好懂、无AI味、不啰嗦、每段不超过3-4行 | 4分 |
| 3. 重点突出 | 频率标签+核心结论+本节要点，三级标注到位 | 4分 |
| 4. 图文并茂 | 对比/分类/多维度信息必须用表格，连续纯文字不超过3段 | 4分 |
| 5. 专业准确性 | 内容专业、无明显错误、覆盖核心考点 | 4分 |
| 6. 内容重叠度 | 跨篇无不必要重复，边界清晰 | 4分 |

### 4.2 抽检规则

- **核心大章**（每科2-4章）：每章抽2-3篇
- **重要章**（每科4-6章）：每章抽1篇
- **普通章**：每2章抽1篇
- 合计15-20篇

### 4.3 整改规则

- **系统性问题**（任一维度平均低于4分）：批量整改，全课程统一处理
- **个别问题**（单篇低于3分）：单篇整改，不影响其他篇
- 整改完后抽整改过的篇复检，确认通过再进收尾

## 五、全量自检（阶段③校验门，不过不进收尾）



* [ ] 知识点篇数 = 92，每组点数与 manifest 一致、唯一归组、无未归类；

* [ ] 每篇四节齐全（学员补充可省），H1/H2/H3 不跳级；

* [ ] 同一知识点已跨讲合并，无按讲重复篇、无 AI 自造组；

* [ ] 篇内题数与 collect 聚合逐项对平（客观题数 / 大题数 / 小问数三项）；主观题已下钻小问、题答由 render_point_qa.py 生成、无遗漏；

* [ ] 无 AI 错题、无考点图谱内容；来源标注完整，冲突按权威度处理；

* [ ] 知识拆解节无应试内容，应试内容全在考试指导节；

* [ ] 关键事实（税率 / 级次 / 年份 / 数字）与讲义、官方解析一致；

* [ ] 组父节点列出全部子页面链接 + 摘要；内部相对链接全部有效；

* [ ] 旧 organized-content/source-materials 已作为输入被消化（为阶段④清退做准备）。

## 六、重生成既有课程（在已有成品上重做，一门一闭环）

> 适用：某课已有一版本地 `知识详解/`，但要用本 SOP 的多智能体方法整体重做（如名师六科、正课税法对齐会计质量）。**新课首次生成走 §一~§五；本节是"在成品上重做"的固定流水线**，门与门之间设人工闸口，不得连做多门。

1. **结构对账（先于动笔）**：以官方大纲为结构权威——`data/_workspace/<profile>/manifest/course-manifest.json` 的 `knowledge.groups[].code / pointIndex`；正课无 course-manifest 时用 `manifest/syllabus_full.json` 加采集口径。现算本地章/点数逐项对账，多出或缺失的篇先查清原因（重复、错拆、漏点），**不新增、不丢失任何官方点，不改官方点名**。
2. **整目录备份（覆盖前强制）**：把该课 `知识详解/` 整体快照到 `data/_workspace/<profile>/regen-backup/<YYYYMMDD-HHMM>/`，核对篇数一致、备份可读后才允许覆盖。旧稿只作只读参照（可借鉴表述），结构与事实以官方大纲和原料为准。
3. **同名同结构原地重写**：章/点的**文件名、标题、层级保持不变**，只重写/加深正文——保证飞书节点树与 `wiki_node_map.tsv` 稳定，后续同步是正文覆盖、不是重建。仍按 §三 多智能体逐章闭环（生成 → 独立检查按 6 维审 → 打回重写 ≤2 次 → 协调者介入），每章过 `code/scripts/okf_validate.py` 硬错误 E=0 才进下一章；四节写法、题答渲染、章 README、全局篇分别按 §二、模板库与写作风格指南。
4. **取材按课型走现成规范**：正课＝讲义 OCR + 视频转写 + 已采集 papers + 学员笔记；名师课(ep3)＝一套主干精讲 OCR + 平台 VTT（[organization §2.12](../knowledge/knowledge-base-organization.md)）。**做题账号风控冻结：不新做题、不造题、不凑 question_count**；题答只用已采集 papers、由 `render_point_qa.py` 渲染；无题可采的点按规范标 N/A，不虚构题量。
5. **整门审核与自检**：全部章完成后做 §四 内容深度审核（抽 15–20 篇、6 维打分）+ §五 全量自检；计数一律现算，与官方大纲、papers 逐项对平。
6. **人工闸口（必须停下，不得自行越过）**：向用户交《闸口报告》＝官方 vs 本地计数对账、`okf_validate` E=0、6 维评分与问题闭环清单、3–5 篇前后对比、备份路径。等用户明确回"通过"或"打回+章节"；打回只重做指定章并复检。
7. **通过后才同步、再开下一门**：用户通过后按 [飞书同步 SOP](wiki-sync-sop.md) 建树 / resync / 双验收（新空间首次建树前按该 SOP 把老空间遗留 `wiki_node_map.tsv` 改名归档）。该门完全闭环后才允许开始下一门。**做哪几门、先后顺序、当前进度属于任务状态，记 TASK_STATUS，本节不固化。**

## 七、常见坑



| 坑                    | 正确做法                                   |
| -------------------- | -------------------------------------- |
| 仍按 "讲" 生成、一讲双文档      | 已废止；按官方知识点跨讲聚合、一篇 4 节（ADR-012）         |
| 凭感觉标高频★              | 用 papers 按知识点聚合题量                      |
| 主观题只取大题顶层            | 下钻 subQuestionList，真答案在小问 analysisText |
| AI 自造分组 / 改官方点名      | 只用官方 14 组 92 点，显式映射 + 脚本 assert        |
| 把 AI 错题、考点图谱当来源      | sources 已否决，禁止                         |
| 学员留言整段照搬（含点赞 / 采集残留） | 只提炼高价值增量入 "学员补充"，吸收后原件归阶段④清            |
