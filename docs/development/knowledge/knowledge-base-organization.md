> **文档类型**：Concept（概念说明 — 知识库组织方法论）

## 一、总体模型：三层解耦、本地与飞书同构

### 1.1 数据三层（物理落点见 DIRECTORY_STRUCTURE）

| 层 | 内容 | 性质 |
|----|------|------|
| 原始资源 | 视频+转写、讲义+OCR（按资源类型分桶） | 永久、传网盘 |
| **知识详解** | **14 组 → 92 知识点篇 + 课程全局篇（本规范对象）** | 成品、可迭代、传网盘并同步飞书 |
| 运行时工作区 `data/_workspace` | 账号级 `_account` + 课程级 `<profile>`（papers/manifest/notes-raw/sniff/tmp/pipeline/logs） | 临时、分层清退，独立于课程目录（ADR-016） |

> 逻辑上三类解耦（原料/成品/过程件）；物理上课程目录只含「原始资源 + 知识详解」两层，过程件统一在 `data/_workspace/`。

### 1.2 知识详解的三级结构（= 飞书三级节点）

```
课程（如【26考季】VIPCPA系列-税法）
└── 官方模块组（如 02_增值税法）         ← 飞书父节点（目录页）
    └── 官方知识点篇（如 增值税税率.md）  ← 飞书子页面（一篇=一个知识点，篇内4节）
```

- **加工单元是"官方知识点"，不是"讲/章"**：同一知识点会在多讲、多套卷出现，必须**跨讲聚合到同一篇**，不得按讲重复建篇。
- 层级深度固定 3 层（课程 / 组 / 知识点篇），知识点内部用 H2/H3 组织，不再为子主题新建页面。

## 二、核心组织原则

### 2.1 只用官方分类，禁止 AI 自造分组

- **组**＝官方教材/课件的模块（税法为 14 组，编号按官方模块序 01–14）；**知识点**＝题目 `knowledgePointList` 的官方标签去重集合（税法为 92 个）。
- **组目录号直接取档案卡 `structure.groups[].code`，跳过无来源的预科组时保留官方 code、不重新连续编号**：不做的组（如会计官方 01 入门/02 衔接，无视频/讲义/题）只留空，正式章从 03 起就建 `03_总论`，不得把它前移成 `01_总论`（前移会与脚本按 code 建目录错位、finalize 重复建章；2026-09-10 已纠正会计此问题）。
- 不得凭 AI 理解新设组、合并/改名官方知识点；官方原名即文件名。
- **归组必须用"显式映射 + 脚本 assert"，不得靠运行时关键词兜底猜**。原因：大量官方知识点名不含税种字样（如"法律责任""税款征收""个人综合所得应纳税额的计算"），纯关键词会误分。做法：
  1. 先按官方标签收集全部知识点；
  2. 对名称不含明确模块字样的**易混点逐条显式指定归属**；
  3. 用脚本 assert 每组点数、总点数无遗漏/无未归类（税法基线 6/14/7/12/10/3/5/2/2/7/3/6/8/7＝92）。
- **已知归并/等价特例（税法）**：土地增值税归组10，不得被"增值税"误归组02；委托加工/应税消费品/进口环节消费税归组03；非居民企业归组04；非居民个人归组05；主观小问泛标签 id=112376"应纳税额的计算"等价并入"增值税一般计税方法应纳税额的计算"。新课程按其官方体系重建映射，不套用本表。
- **来源形态变体（名师课 ep3 / 无 papers）**：当课程在风控期或平台本就没有 `papers.knowledgePointList` 时（如 ep3 名师专业课），不靠题目标签定结构，改为：**组＝outline 全面精讲章树（code 对齐同科目正课、不连续重编号）；知识点＝讲次目录去 `NN_` 前缀与分 P 后缀后聚合**（同一知识点的多个分 P 合并一篇）。归组仍走"显式映射 + 脚本 assert"（`ep3_build_manifest.py` 生成 manifest、回写 config.structure），重点强化跨章专题/考前冲刺不单独建组、跨讲融入对应章或全局篇。此变体只换"结构与来源"，成品四节骨架、frontmatter 词表、校验门不变（差异表见 [KNOWLEDGE_BASE_TEMPLATE.md 两种来源形态](../templates/KNOWLEDGE_BASE_TEMPLATE.md)）。
- **名师课 manifest 读取口径（易踩坑，逐章开写前先钉死）**：文件 `data/_workspace/ep3-{subject}-2026/manifest/course-manifest.json`，先取顶层 `['knowledge']`；遍历 `groups[]` 时其 **`code` 是整数**（如 9/10/11，不是零填充字符串 `'09'`，按整数比较）；组名取 `.name`、本组点取 `.pointIds`；单个知识点用 **`pointIndex[str(pid)]`（键是字符串）** 取 `{title, lessonDirs, teachers, stage, chapter}`。**章目录名＝两位 `NN_` ＋ 组名原样**，组名里的顿号、标点一律保留，不自行改写。

### 2.2 一个知识点一篇、篇内 4 节（知识与应试"分节"不"分文档"）

旧范式把"知识本身"和"考试指导"拆成两个文件；新范式在**同一篇内分节**，并补入题答与学员补充，固定四个二级标题：

| 节 | 内容 | 主要来源 |
|----|------|----------|
| 一、知识拆解 | 客观知识：定义/特征/分类/原则/表格/结构化要点 | 讲义 OCR + 转写为主干 |
| 二、考试指导 | 考情、高频（用题量定）、易错、口诀、技巧 | 官方解析 + 转写口诀 + 用户笔记 |
| 三、题答解析 | 本知识点全部题：题面/选项/标准答案/官方解析 | papers（题/标准答案/官方解析） |
| 四、学员补充 | 学员高价值讨论、助记、易错补充（无则省略本节） | 清洗后的用户留言/笔记 |

### 2.3 跨讲聚合、不按视频时间线

- 以知识点为索引，把分散在多讲视频、多份试卷中的同一主题内容合并去重；
- 不按视频播放顺序堆内容；老师在不同时间重复讲同一点要合并；
- 层间"讲↔资源↔知识点"的对应关系由 `data/_workspace/<profile>/manifest/course-manifest.json` 承载，规范本身不写具体课程映射。

### 2.4 Answer-First（答案优先）

每个子主题开头先给核心结论，再展开背景。AI 检索优先抽取段首，结论在前提高命中率。

### 2.5 Atomic Structure（原子结构）

每段只讲一个具体问题，不混合多个主题，便于精确检索、减少幻觉。

### 2.6 Strict Hierarchy（严格层级）

- H1＝知识点篇标题（官方知识点名）；H2＝固定四节；H3＝节内子主题；必要时 H4，不跳级。
- 不再使用"第N节/章"这种讲次结构作为知识详解骨架。

### 2.7 Context Block（上下文块）

每篇开头用引用块标注：所属组、来源（讲义X份/转写X讲/题X道）、适用考季、更新时间。让 AI 知道内容适用边界。

### 2.8 MECE 分类

每个知识点唯一归属一个组（互斥），全部官方知识点都能归位（穷尽）。由脚本校验：无重复归组、无未归类、总数与官方标签去重数一致。

### 2.9 冲突处理与来源优先级

用户笔记/留言与既有知识冲突时，**不得直接覆盖**，按权威度验证后处理：

**讲义/官方教材 ＞ 官方解析 ＞ 高赞用户笔记 ＞ 普通用户笔记**

- 用户笔记中经验证准确、且知识库没有的点 → 补入对应节；
- 冲突且未验证 → 暂不修改，记入待核；
- 自动化作业产生的"AI 错题"不是用户产出，一律不作来源。

### 2.10 新知识点处理

- 发现"新点"先在 papers 官方标签里核对：若官方已有对应知识点，归并到该篇，不新建；
- 若确为官方标签未覆盖、但讲义明确讲解的点，归入对应组、在 manifest 标注"官方未标-讲义补充"，**不新建 AI 自造的组**；
- 每次做题、读解析、整理留言后都要做一次这一检查。

### 2.11 飞书 Aily 知识空间 6 原则（沿用）

| 原则 | 本项目应用 |
|------|-----------|
| 一题一段 | 一个子主题独立成段 |
| 口语对齐 | 标题兼顾用户问法，同义表述用顿号列出 |
| 300 令牌 | 单段尽量≤约450字，过长拆段 |
| 时效可见 | 标注考季/适用时间（如"26考季"） |
| 层级分类 | 课程/组/知识点 3 层，便于向量过滤 |
| 0 敏感 | 不含个人隐私、账号权限信息 |

### 2.12 名师课精讲 OCR 取材与大文件作业法（风控期 AI 直接成稿）

风控期 `tmp/point-questions` 为空、assemble/render 链路不走，由 AI 直接读精讲 OCR + 转写写成稿，逐章闭环。为稳定产出、避免漏读/重读，固定如下作业法：

1. **一科选一套体系最完整的老师精讲 OCR 作"主干"**，同科其他老师稿只作补充，不平行混用。审计＝王依然《严控定制》上/下册 OCR 为主干、转写只补口诀考频，陈岩全一册/强化/冲刺/基础稿作补充；仅个别章另有独立课件（审计为第 03/17/18 章）时才把该课件加入 sources。选谁作主干以"章节覆盖连续、表格/真题齐全"为准，开新科前先 `ls 原始资源/notes/` 比对再定。
2. **manifest 先钉死再读 OCR**：按 2.1 口径从 manifest 取出本章每个 point 的 title / lessonDirs（跨几讲），再用 `awk 'NR>=a&&NR<=b&&/^第[一二三四五六]节/'` 在主干 OCR 里定位章/节行边界（下一章起点 = 本章结束行），把每个 point 映射到确定行区间。
3. **大 OCR 单文件分段 Read**：主干 OCR 常达 3 万行，单次按约 150–210 行分段读尽该 point 区间后立即成稿，不凭记忆写；续用前先 grep/awk **复核行边界**（文件未变但行号要当场再确认）。
4. **OCR 噪声还原**：macOS Vision OCR 含页眉乱码、表格被拆成多行碎片、数字/方向（同向反向）错位，成稿按审计准则规范表述与语境还原，不照抄错位方向/数字；定义以讲义 OCR 为准、转写仅补考频口诀。
5. **一章一闭环**：本章全部 point 成稿 → 手写章 README（type:ChapterIndex、point_count）→ `python3 code/scripts/okf_validate.py "<章目录>"` 要求硬错误 E=0（W80 指向未写章的前向链接、W81 顶层孤儿页属预期）→ 磁盘 find 现算计数 → 回写 `three_tracks_status.md` 与 TASK_STATUS → 一个章一个 commit 并 push。

## 三、题答解析的组织（数据层面）

> **格式规范（怎么排版给考生看）见 → [写作风格指南§4.3](./knowledge-writing-style-guide.md#43-第三节题答解析)**，本节只讲数据从哪来、怎么聚合。

- **客观题（type=1/2 等）**：题面（去 HTML）、选项、标准答案、官方解析；同知识点多题聚合，可按题型/难度排序。
- **主观大题（type=5 容器）必须下钻 `subQuestionList`（type=6 小问）**：按"大题题干 → 小问(1)…(n)"组织；小问标准答案常为"见解析"，**真正答案/算式在小问 `analysisText`**，不得只取题顶层（顶层为空会漏）。
- 题量用于第二节"高频考点"判定，并与 manifest 对账（篇内题数合计 = 该知识点标签题数）。

## 四、组父节点（目录页）规范

每个官方模块组是飞书父节点/本地组目录的索引页，**只做目录、不承载正文知识点**。必须包含：

1. 组信息块：组名、覆盖知识点数与题量、来源、适用考季、更新时间；
2. **子知识点页面清单**：每篇一个可点击链接 + 一句摘要；
3. 组概述：本组主线与学习目标（3–7 条重点）；
4. 学习建议：学习顺序、与相邻组的关系。

模板见 [KNOWLEDGE_BASE_TEMPLATE.md](../templates/KNOWLEDGE_BASE_TEMPLATE.md)。当某知识点篇过长（超约 5000 字或 10 个以上 H3），优先在篇内分 H3，不轻易再拆页面；确需拆分时父节点清单同步更新。

## 六、AI 问答优化

- **FAQ**：知识点篇末可加"常见问题"，问题+答案，便于直接匹配；
- **关键词标签**：篇首标注关键词/同义表述；
- **交叉引用**：相关知识点之间用飞书页面链接/锚点互链（如"增值税一般计税"互链"进项税额""销项税额"），帮助 AI 建立关联。

## 七、结构层面质量检查清单（每篇/全量生成后必过）

> **内容质量检查（写得好不好）见 → [写作风格指南§九](./knowledge-writing-style-guide.md#九质量检查清单每篇必过)**，本节只查结构对不对。

| 检查项 | 标准 |
|--------|------|
| 结构同构 | 本地 知识详解 与飞书均为 课程→组→知识点 三级 |
| 数量闭合 | 知识点篇数 = 官方标签去重数，脚本 assert 各组点数 |
| 唯一归组 | 每个知识点只属一个组，无未归类、无重复 |
| 一篇四节 | 四节齐全（学员补充可省），H1/H2/H3 不跳级；**无 papers 来源期第三节保留标题+回补占位、不渲染空分类，status=draft，回补齐后升 stable** |
| 跨讲聚合 | 同一知识点已合并多讲/多卷，无按讲重复篇 |
| 题量对账 | 有 papers：篇内题数与 manifest 标签题数一致、主观题已下钻小问；**无 papers（名师课/风控）：此项 N/A，改校验 sources 无 paper-* 、frontmatter 无 question_count、多老师 sources 齐** |
| 父节点 | 组父节点含全部子页面链接+摘要，无空节点/重复节点 |
