## 一、知识库层级结构

```
CPA备考知识库（根）
└── 课程库
    ├── 通用做题思路解析.md                 ← 跨课通用方法论（CPA 层，全课共用一份）
    └── 【26考季】VIPCPA系列-税法（蔡俊峻老师）/   ← 课程根节点
        ├── 01_税法总论/                    ← 官方模块组（父节点=目录页）
        │   ├── 税法概念.md                 ← 官方知识点单篇（一篇=一个知识点，篇内4节）
        │   ├── 税法原则.md
        │   └── …（本组 N 个知识点）
        ├── 02_增值税法/
        │   └── …
        ├── …（共 14 组、92 篇）
        ├── 课程做题思路解析.md             ← 课程全局篇（带本课程特征）
        └── 考试指导速查手册.md             ← 课程全局篇（只通用，冲刺后定稿）
```

- 层级固定 3 层：课程 / 组 / 知识点篇；知识点内部用 H2/H3，不再为子主题建页面。
- 组编号 `NN_` **直接用课程档案卡 `structure.groups[].code`（官方组号）**；知识点文件名用官方知识点原名。
- **跳过无来源的预科组时保留官方 code、绝不重新连续编号**（教训：会计官方 01 入门/02 衔接是无视频/讲义/题的预科、正式章从 03 总论起；曾把总论重编成 `01_总论`、其后又沿用官方 04，造成 `01→04` 跳号且与脚本按 code 建目录错位，finalize 会重复建章，已于 2026-09-10 改回 `03_总论`）。即"不做的组号留空"，而不是"把后面的组往前挪"。
- 本地 `知识详解/` 与飞书**同构**：本地目录=飞书父节点，本地 .md=飞书子页面。

## 三、知识点单篇模板（核心，一个知识点一篇）

> 固定四个二级标题：一、知识拆解 / 二、考试指导 / 三、题答解析 / 四、学员补充；三、题答解析之后、四、学员补充之前固定设「## 关联知识点」导航节。**第四节无内容时整节省略**，其余三节为必备。
>
> **可读性优化原则（2026-09-17起统一执行）**：
> 1. **结构清晰**：每节开头增加「本节要点」摘要（3-5条），让读者快速抓住重点
> 2. **语言简练**：精简冗余描述，用表格、对比、列表替代大段文字；每段不超过3-4行
> 3. **图文并茂**：优先使用表格、对比表、流程图（用文字描述或Mermaid）、思维导图结构；避免纯文字堆砌
> 4. **重点突出**：标签白名单（禁止自造）——三级频率【必考】/【高频】/【了解】（互斥）+ 辅助【易错】/【新增】/【记忆】（可叠加）；易错点正文与汇总表双向挂钩；用**粗体**突出关键结论
> 5. **分层阅读**：核心结论前置（Answer-First），详细解释后置；满足不同深度的阅读需求

**硬性约束**：
- 主观题**必须下钻 `subQuestionList`**，禁止只取大题顶层（顶层 answer/analysis 为空会漏，真答案在小问 analysisText）。
- **题答解析由脚本确定性生成、AI 不手抄算式数字**：`collect_point_questions.py` 按知识点聚合 → `render_point_qa.py` 渲染第三节初稿；AI 只写第一/二节并校核题答，不改动题面、答案、算式本身。
- **空分类不渲染**：客观题或计算/综合大题任一分类题量为 0 时，整段（含 `###` 分类标题）不输出；`render_point_qa.py`、`assemble_point.py` 均以 `if groups:` / 题量判断包裹，不得无条件写分类标题。
- **公式与算式分工**：可复用的公式/规则/对照表放"一、知识拆解"，每道大题的具体算式演练放"三、题答解析"，两处不重复堆叠。
- **计算大题全收不折叠**：以"大题"为不可拆单位全部收录（每道是完整业务情境），不做"典型题＋其余索引"，靠 `#### 大题N` 导航；篇幅长不构成删减理由。
- 每题标注来源卷与 paperId；剔除自动化作业产生的 AI 错题。
- 篇内题数（客观数 / 大题数 / 小问数）须与 collect 聚合结果逐项对平（质量门）。
- **frontmatter 标准档（机器权威，与顶部人读 Context Block 对齐、不重复维护）**：`type` 只用 KnowledgePoint / ChapterIndex / Reference 三词表；`tags` 用英文 slug（`cpa,{subject-slug},26-season,chapter-{NN}`，组号取官方 code）；`sources.lecture.resource` **著录到讲目录 `原始资源/notes/{NN_讲名}/`**（成品为目录内 `*_OCR.md`），不指单个 PDF/PDF 改名即断链；transcript 指 `videos/{NN_讲名}/transcript.md`；题目用 `paper-{id}`+`paperId {id}`。飞书同步由 `resync_wiki_content.py` 自动剥离顶部 frontmatter，读者只看正文。标准字段全表见 AGENTS.md §3.12。

| 知识点来源 | `knowledgePointList` 官方标签去重 | 讲次目录去 `NN_` 前缀、去分 P 后缀后聚合（多个分 P 合并一篇，如 4003 聚合 12+13 两讲） |
| sources | lecture/transcript/**paper-{id}** | `transcript-{老师}` / `handout-{老师}` 区分多老师，**无 paper** |
| 多老师 | 通常单老师 | 成品**融合去重、不区分老师**（老师名只留在原始资源文件名层）；可加 `teachers`、`point_id` 扩展字段 |
| question_count | 有，且与聚合对平 | **整行省略**（不写 0） |
| 第三节 | 脚本确定性渲染客观/大题 | 无来源时**保留节标题 + 一段占位**：说明因何缺（如风控码）、解除后用何命令回补、draft→stable；**不渲染空分类标题** |
| 第四节 | 有学员内容则写 | 无内容整节省略 |
| status | stable | **draft**，题答/笔记回补齐后升 stable；Context Block 增一行说明（双老师融合 / 风控占位） |

## 四、模块组父节点模板（章 README＝目录页，不承载正文）

> 事实结构以 108 篇成品为准：frontmatter `type: ChapterIndex`，正文固定「本章概述 / 知识点列表 / 重点内容 / 学习建议」四节（方案D标准，2026-09-16起统一）。
>
> **必须包含**：
> 1. **信息块**：名称、覆盖知识点/题量、来源、适用考季、更新时间；
> 2. **本章概述**：2–4 句，只讲本章定位、考试地位和学习目标，**不含核心考点**（核心考点放"重点内容"）；
> 3. **知识点列表（表格形式）**：序号 | 知识点（本地源文件用相对链接，同步时转成飞书 `<cite>` 内部引用）| 核心内容（一句摘要）；表格信息密度高，便于快速浏览；
> 4. **重点内容（独立成章，3–7 条）**：每条粗体标题 + 简述，便于考前快速复习定位；
> 5. **学习建议**：3–6 条，学习顺序、与相邻章关系、投入建议。
>
> **不包含**：正文知识点内容（父页面只做目录，正文在知识点子页面）；与子页面重复的框架；流程/维护说明（归工程文档，不进飞书）。

## 九、父节点使用说明

### 创建步骤
1. 先建子页面（知识点篇/模块组），在 `logs/wiki_node_map.tsv` 登记各自 node/obj token；
2. 本地源文件用相对链接 `[标题](./标题.md)` 填写目录清单，链接文字等于目标文件名；
3. 填写概述、重点、学习建议；
4. 同步管道（`wiki_link_resolve.py` → `docs +update`）自动把相对链接转成飞书 `<cite>` 内部引用写回；
5. 回读验证 cite 的 doc-id 全部可达、清单不缺不重；导航型页面（课程根、章 README）顶部各有 1 处左侧树单窗口导航说明。

### 更新步骤
1. 子页面新增/重大更新/状态变化时，同步父节点清单、题量、摘要与重点；
2. 改完回读，确认父清单与实际子节点一致。

### 注意事项
- **本地源文件用相对链接，飞书成品是 `<cite>` 内部引用**：不要在正文里手写完整 `/wiki/<node>` URL（冗长、易随节点变动失效、无法结构化校验）；注意 cite 点击同样新开标签（飞书正文跨文档链接固定行为），单窗口连续阅读靠左侧知识库目录树；相对链接到 cite 的转换由 `wiki_link_resolve.py` 统一完成，外链才用完整 URL；
- 模块组下必须列全本组知识点（表格形式），课程根下列全 14 章；
- 重点控制 3–7 条；**概述简洁（2-4句）且不含核心考点**，核心考点放"重点内容"；父节点不写正文知识点；
- 任何飞书写操作前先读 lark-wiki / lark-doc 的 SKILL，本地是源头、不在飞书直接编辑正文。
