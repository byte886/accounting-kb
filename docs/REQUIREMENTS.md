## 1. 项目背景与目标

### 1.1 背景

用户购买了高顿教育的CPA课程（税法、会计等），课程包含视频直播、讲义文档和课后练习。但课程平台存在以下问题：

- 课程有有效期，到期后无法观看
- 视频内容无法搜索，复习时需要从头播放
- 讲义和视频内容分散，难以系统整理
- 课后练习的错题和解析无法沉淀为个人知识
- 平台交互效率低，需要自动化工具提升采集和生成效率

### 1.2 核心诉求（一句话）

**通过高顿教育平台的视频和考试来完成一个个人知识库系统，同时提供视频和文档的永久备份。**

### 1.3 最终目标

用户最终获得：

1. **一个永不失效的课程资料库** — 所有购买的CPA课程视频和讲义保存在本地和百度网盘，平台到期也能看
2. **一个可搜索的个人知识库** — 视频里老师讲的、讲义上写的、做题中学到的，全部变成文字，按课程章节组织在飞书知识库里，随时搜得到
3. **一个会做题的备考助手** — 学完直接做课后练习，知识库帮你找答案、对依据、查漏补缺
4. **一个自动化的采集生成系统** — 可以方便地指定课程、自动完成采集和生成、支持断点续传、持续优化流程

## 2. 核心功能需求

### 2.1 自动化采集与生成系统（核心）

#### 2.1.1 课程指定与任务管理

- **需求**：过程中可以方便地指定哪些课程需要去采集和生成
- **实现方式**：
  - 配置文件指定课程列表（课程名、老师、课次范围）
  - 任务状态跟踪（未开始/进行中/已完成/异常）
  - 支持单个课程、批量课程、指定课次范围
  - 课程索引文档记录所有课程清单、进度、资源位置
- **验收标准**：修改配置文件后运行脚本，能自动识别需要处理的课程

#### 2.1.2 自动化流程执行

- **需求**：自动化完成从采集到生成的完整流程
- **完整流程**：建目录 → 下载视频 → 下载文档 → 同步网盘 → 内容解析 → 知识库(第一阶段：初始生成) → 做题验证 → 知识库(第二阶段：迭代更新) → 任务报告
- **实现方式**：
  - 主流程脚本 orchestrator，按顺序调用各环节脚本
  - 每个环节独立脚本，可单独运行
  - 支持从任意环节开始执行（断点续传）
  - 每个讲座独立走完一遍流程，完成后再进入下一个
- **验收标准**：指定课程后，无需人工干预即可完成完整流程（登录等敏感操作除外）

#### 2.1.3 断点续传与任务接手

- **需求**：可以根据已经完成的部分工作来接手完成整个课程的其它工作
- **实现方式**：
  - 每个环节完成后生成状态标记文件（如 `.downloaded`、`.compressed`、`.uploaded`）
  - 任务状态文件记录每个环节的完成情况
  - 重新运行时自动跳过已完成环节，从断点继续
  - 异常中断后可恢复执行
  - 大任务执行状态记录与异常恢复机制
- **验收标准**：中断后重新运行，能从断点继续，不重复已完成工作

#### 2.1.4 流程优化与迭代

- **需求**：可以方便优化采集过程
- **实现方式**：
  - 每个环节的参数可配置（压缩参数、OCR参数、转写模型等）
  - 操作日志记录每个环节的耗时、成功率、异常情况
  - 问题跟踪文档记录发现的问题和解决方案
  - 工作流文档持续更新优化
  - 测试驱动原则：每个新功能/新流程先做单样本测试，验证通过后再批量执行
- **验收标准**：修改配置参数后能立即生效，优化效果可量化对比

### 2.2 视频采集与处理

#### 2.2.1 视频下载

- **需求**：从高顿平台下载课程视频
- **技术方案**：HLS AES-128 解密下载（Playwright + Node.js）
- **特殊规则**：
  - 跳过开班典礼（可配置是否跳过，开班典礼用序号00作为第一讲处理）
  - 视频下载完成后关闭播放页面
  - 使用后台下载，不弹出Chrome下载确认框
  - 下载前梳理所有视频和文档清单，方便检查完整性
- **验收标准**：下载的视频可正常播放，时长与原始一致

#### 2.2.2 视频压缩

- **需求**：压缩视频到清晰但空间占用小的体积
- **技术参数**：
  - 编码：H.265 (libx265)
  - CRF：30（课件文字清晰、头像略糊但不影响学习）
  - preset：fast
  - 音频：AAC 96kbps
  - 标签：hvc1（Apple设备兼容）
  - faststart：开启（支持边下边播）
- **目标体积**：单视频控制在300MB左右（2.5小时视频），控制不到可调整分辨率
- **运行方式**：必须通过iTerm运行，可实时查看进度，任务完成后关闭窗口
- **验收标准**：压缩后视频文字清晰、声音清楚、体积在可接受范围

#### 2.2.3 视频完整性验证

- **需求**：验证下载和压缩后的视频完整可用
- **验证项**：
  - 时长对比（与原始视频误差<2秒）
  - 编码格式验证（H.265 + AAC）
  - 可播放性验证
  - 不完整视频自动重新处理
- **验收标准**：所有视频通过验证，不完整视频自动重新处理

### 2.3 文档采集与解析

#### 2.3.1 讲义文档下载

- **需求**：下载课程中的讲义文档（PDF/PPT/DOC）
- **特殊规则**：
  - 使用后台下载（curl），不弹出Chrome下载确认框
  - 下载到指定目录（`docs/`）
  - 下载后验证完整性
  - CDN直链获取，避免通过浏览器下载
- **验收标准**：所有讲义文档下载完整，可正常打开

#### 2.3.2 文档文字提取（OCR）

- **需求**：从讲义文档中提取文字内容
- **技术方案**：统一使用macOS Vision框架（系统原生）
- **特殊规则**：
  - PDF中的图片需要OCR识别
  - 表格和图表需要识别（OCR不准确时用AI补充）
  - 提取的文字输出到 `docs_text/` 目录（OCR文字稿的标准存放位置），后续合并到知识库
  - 运行方式：通过iTerm运行
- **验收标准**：文档文字提取完整，表格和图片内容可识别

### 2.4 音频转写

#### 2.4.1 视频音频转文字

- **需求**：将视频中的语音转写为文字
- **技术方案**：FunASR SenseVoiceSmall + fsmn-vad（开源本地方案，成本可控）
- **成本控制**：目标10-20元/课程（如使用付费API），优先使用开源本地方案
- **输出**：
  - `transcript.md` — 可读文字稿
  - `transcript.json` — 原始数据（含时间戳，技术过程文件不上传网盘）
- **运行方式**：通过iTerm运行，支持批量转写
- **验收标准**：转写准确率满足学习需求，专业术语识别正确

### 2.5 知识库生成（两阶段）

#### 2.5.1 第一阶段：初始生成

- **需求**：基于讲义和视频内容生成知识库
- **来源**：讲义OCR + 视频音频转写
- **核心原则：知识本身与考试指导分离**

> 🔁 **演进（ADR-012，2026-09-04）**：不再拆"知识拆解.md / 考试指导.md"两个文档、两个子节点；改为**一个官方知识点一篇、篇内固定 4 节**（一知识拆解/二考试指导/三题答解析/四学员补充），父节点为 14 个官方模块组，成品在课程目录 `知识详解/`。下表与"输出结构"为初始需求，保留追溯，现行以 ADR-012 与 KNOWLEDGE_BASE_TEMPLATE 为准。

| 文档 | 内容 | 用途 | 本地文件名 | 知识库节点名 |
|------|------|------|-----------|-------------|
| **知识拆解** | 知识本身（定义、特征、分类、表格、结构化知识点） | 应用、搜索、AI问答 | `知识拆解.md` | `知识拆解` |
| **考试指导** | 考试指导（考点、易错点、记忆口诀、真题、考情、学习建议） | 备考、应试 | `考试指导.md` | `考试指导` |

- **输出结构**：
  - 每个章节一个父节点（如 `01税法总论`）
  - 父节点下分「知识拆解」和「考试指导」两个子节点
  - 父节点内容包含子节点链接和章节概述（父页面规范）
- **父页面（目录页）规范**：
  - 基本信息块：课程/章节名称、主讲老师、整理来源、适用范围、更新时间
  - 子节点目录清单：知识拆解和考试指导两个子文档的可点击链接
  - 章节概述：简要介绍本章节的主要内容和学习目标
  - 重点内容：列出本章节的核心知识点（3-7条）
  - 学习建议：给出学习顺序和方法建议
- **内容分类**：
  - **知识拆解**：知识点本身（概念、定义、原理、公式），面向应用和搜索，只保留客观知识点
  - **考试指导**：考点、易错点、记忆口诀、真题解析，面向考试，按"考情分析→高频考点→易错点→记忆口诀→真题回顾→学习建议"组织
- **知识库来源优先级**：
  1. 视频转写文字（主要来源）
  2. 讲义文档（交叉印证）
  3. 讲义OCR文字（图片中的表格、图表）
  4. 做题验证中发现的遗漏知识点（补充）
- **冲突处理**：讲义与视频内容冲突时，以讲义为准
- **验收标准**：知识库内容完整、结构清晰、分类准确

#### 2.5.2 第二阶段：迭代更新

- **需求**：基于做题过程补充和优化知识库
- **来源**：题与标准答案、官方解析（`collect_paper_sources.js` 接口采集为 papers JSON）＋用户笔记；自动化作业产生的 AI 错题不作为来源
- **更新内容**：
  - 补充易错点和记忆口诀
  - 补充真题解析
  - 纠正常识错误
  - 补充用户笔记精华
- **新知识点补充原则**：
  - 在做题、收集解析、整理用户留言等任何过程中，如果发现新的知识点，都必须补充到知识拆解文档中
  - 非指导考试的知识点（如知识的背景、扩展应用、跨学科联系、实际案例等）同样需要补充到知识拆解中
  - 知识拆解的目标是构建完整的知识体系，不仅服务于考试，也服务于知识应用、搜索和AI问答
- **冲突处理**：
  - 用户笔记与知识库冲突时，以原知识库（讲义）为准
  - 验证顺序：讲义/官方教材 > 官方解析 > 高赞用户笔记 > 普通用户笔记
  - 未经验证的用户笔记内容，不得直接修改知识库拆解
- **验收标准**：做题中发现的问题都已反映到知识库中

### 2.6 做题验证与反馈

#### 2.6.1 检查作业情况（建目录阶段必须执行）

- **需求**：在开始每个讲次的任务时，必须检查该讲次是否有课后作业（"继续考"）
- **检查时机**：在建目录阶段（查看课程表页面时）就必须检查，而不是等到做题验证阶段
- **检查方法**：
  1. 打开高顿教育课程表页面
  2. 找到对应讲次，查看是否有"继续考"或"做作业"按钮
  3. 如果有按钮，说明该讲次有课后作业，需要在后续流程中执行做题验证
  4. 如果没有按钮，说明该讲次无课后作业，在任务报告中明确说明
- **常见情况**：
  - 开班典礼（00）：通常无作业
  - 正式章节（01+）：通常有作业
  - 冲刺模考：有机考和视频解析
- **任务报告要求**：不允许写"待确认"或"待检查"

#### 2.6.2 课后练习做题

- **需求**：完成每个章节的课后练习，验证知识库质量
- **流程**：
  - 先根据知识库内容学习，然后应答题目
  - 做错了可重新做，直到完成
  - 所有章节练习完成后，再做总考试（可能有多个）
- **做题前必须查询知识库**：每道题都要严格从知识库先查询答案，禁止凭印象猜测
- **交互优化**：
  - 单选题和多选题分别处理（使用不同脚本）
  - 补题流程：通过答题卡单独挑选未做题，不从头依次做，避免反向选择取消已选项
  - 避免反向选择取消已选项（点击已选项会取消选择，必须检查）
  - 时间到了直接稍后提交
  - 页面管理：操作前检查标签页数量，关闭多余页面，优先在未完成试卷页面操作
  - 页面异常时先刷新或重新打开，不要在异常页面反复尝试
- **技术方案**：使用JavaScript直接点击选项（v4方案），不依赖ref属性
- **验收标准**：所有课后练习完成，错题有记录和分析

#### 2.6.3 错题反馈与知识库补充

- **需求**：将错题涉及的知识点补充到知识库
- **流程**：
  - 分析错题原因（知识库错误/未参考知识库/交互错误）
  - 知识库错误则纠正
  - 未参考知识库则优化做题流程（强制查询知识库）
  - 交互错误则优化交互脚本
- **验收标准**：错题原因都已分析，相应问题都已解决

#### 2.6.4 用户笔记和解析收集

- **需求**：收集每道题的官方解析和用户留言
- **内容**：
  - 官方解析（每道题都要收集，包括答案解释、解题思路）
  - 用户留言精华（高赞留言、有价值的补充、记忆口诀）
- **收集方式**：
  - 遍历所有题目（点击下一题）
  - 有的题目没有用户留言（空白），记录为空
  - 尽可能获取所有用户留言（向下滚动抓取）
- **价值**：
  - 验证知识库准确性
  - 补充记忆口诀和易错点到考试指导
  - 发现新知识补充到知识拆解
- **验收标准**：所有题目的解析和有价值的用户留言都已收集

#### 2.6.5 冲刺模考

- **需求**：完成所有课程后进行冲刺模考
- **内容**：
  - 机考（交互与一般课程考试不同，需要单独补充交互规范）
  - 视频解析（视频走一般视频处理流程）
- **处理顺序**：先视频解析，后机考
- **验收标准**：冲刺模考完成，机考交互规范补充到文档

### 2.7 百度网盘管理

#### 2.7.1 文件上传

- **需求**：将视频和文档上传到百度网盘备份
- **技术方案**：百度网盘开放平台API（优先），Playwright操作网页版（备选）
- **目录结构**：与本地完全镜像
- **特殊规则**：
  - 上传不通过代理（直连），避免网速慢
  - 技术过程文件不上传：任务过程记录、TRANSCRIPT.json等只是技术过程不是直接面向使用者的文档（验证默认不单独成文）
  - 上传后验证完整性
  - 上传标记文件 `.uploaded` 记录已上传状态
- **验收标准**：网盘文件与本地一致，目录结构正确

#### 2.7.2 目录组织与管理

- **需求**：在网盘上组织目录，支持删除、新建、移动等操作
- **技术方案**：优先使用API，效率低时用Playwright
- **验收标准**：网盘目录可正常管理，操作可追溯

### 2.8 任务报告与状态管理

#### 2.8.1 任务报告

- **需求**：每次任务生成报告，记录执行情况
- **内容**：
  - 任务范围（课程、课次）
  - 各环节完成情况
  - 耗时统计（大概即可，不需要太准确）
  - 视频/文档下载状态和文件大小
  - 压缩参数和最终体积
  - 遇到的问题和解决方案
  - 知识库更新情况
  - 做题结果
  - 缺陷统计（按严重程度和优先级分类）
  - 下一步建议
- **存放位置**：飞书文档 + 本地 `data/_workspace/<course>/task-reports/` 目录
- **验收标准**：每次任务都有报告，内容完整可追溯

#### 2.8.2 任务状态跟踪

- **需求**：实时跟踪任务状态，方便查询和接手
- **唯一权威来源**：`project-management/TASK_STATUS.md`（Markdown文档）
- **飞书Base**：保留作为可视化模板，供其他同事参考，不日常更新（避免双轨维护）
- **内容**：
  - 课程列表和进度
  - 每个课次的各环节状态
  - 问题和风险
  - 任务有层级关系（用编号表示，如 2.1、2.1.1）
- **状态标记**：✅完成 / 🔄进行中 / ⏳待启动 / ⚠️有阻塞/问题 / ❌已取消/不做
- **常用查询话术**：
  - "查询任务状态：还有哪些待完成的任务？"
  - "查询问题：当前有哪些未解决的问题或BUG？"
  - "查询维护：当前有哪些待完成的维护工作？"
  - "查询概览：给我一个项目整体状态的总结"
- **验收标准**：任务状态实时更新，可随时查询当前进度

## 3. 非功能需求

### 3.1 性能要求

| 任务 | 性能目标 |
|------|----------|
| 视频压缩 | 10倍速以上（2.5小时视频≤15分钟） |
| 音频转写 | 15倍速实时以上 |
| OCR | 单文档≤1分钟 |
| 大任务检查 | 最大5分钟检查一次进度，禁止等待10分钟以上不检查 |

### 3.2 成本控制

- 音频转写：优先使用开源本地方案（FunASR），付费API控制在10-20元/课程
- 视频压缩：本地CPU/GPU处理，无额外成本
- 存储：本地+百度网盘，控制视频体积在300MB/2.5小时左右

### 3.3 可靠性要求

- 所有环节支持断点续传
- 异常中断后可恢复
- 关键操作有验证步骤
- 不完整文件自动重新处理
- 大任务执行状态记录与异常恢复机制

### 3.4 可维护性要求

- 脚本参数可配置
- 文档完整（工作流、脚本说明、问题跟踪）
- 代码有注释
- 新增功能不影响已有功能
- 文档维护规则：新增文档必须在文档地图中登记，删除/移动必须更新引用

### 3.5 安全性要求

- Token等敏感信息加密存储（用主密码加密，主密码由用户保管、不写入仓库；加密文件(.enc)可提交到GitHub）
- 不提交大文件到GitHub（>10MB阻止，pre-commit hook检查）
- pre-commit hook检查敏感信息
- GitHub仓库默认公有

### 3.6 可扩展性要求

- 支持后续不断增加新的课程
- 支持新的交互场景（如机考）的多轮迭代测试
- 知识库支持AI学习、AI搜索、智能问答等未来需求
- 知识库发展与重设计原则：何时重设计、重设计原则、扩展原则、变更管理流程

### 3.7 系统要求与平台兼容性

> ⚠️ **项目主要在 macOS 下开发和运行**，部分工具依赖 macOS 原生功能。

**支持的平台**：
- ✅ macOS 12+：完全支持（主要开发和运行环境）
- ⚠️ Linux：部分支持（需替换 OCR 方案，终端工具不同）
- ⚠️ Windows：部分支持（需替换 OCR 方案，bash 脚本需 WSL）

**Mac 专用工具（不可直接跨平台）**：
- macOS Vision 框架：PDF/图片 OCR 文字提取
- iTerm2：批量任务前台运行（实时进度）
- textutil：DOC/DOCX 文字提取
- AppleScript：iTerm 窗口控制
- bash 3.2：脚本运行环境（Mac自带版本）

**跨平台工具（可直接使用）**：
- ffmpeg、Playwright CLI、Node.js、Python 3.10+、FunASR/faster-whisper、百度网盘API、飞书API

**硬件要求**：
- CPU：建议 8 核以上（视频压缩和音频转写耗时较长）
- 内存：建议 16GB 以上（转写模型加载需要）
- 磁盘：建议 500GB 以上（原始视频 + 压缩视频 + 转写中间文件）
- 网络：稳定的互联网连接（视频下载、网盘上传、飞书API）

## 4. 特殊规则与约束

### 4.1 课程相关

- **跳过开班典礼**：默认跳过开班典礼（可配置），开班典礼用序号00作为第一讲处理
- **总考试在所有课后练习完成后做**
- **冲刺模考在所有课程完成后进行**
- **入口找不到时尝试3次操作**，3次找不到再问用户

### 4.2 内容处理

- **讲义与视频内容冲突**：以讲义为准
- **用户笔记与知识库冲突**：以原知识库（讲义）为准，验证顺序：讲义/官方教材 > 官方解析 > 高赞用户笔记 > 普通用户笔记
- **非考试知识补充**：放到「知识拆解」，不硬拆，分析不出来或没有价值就放弃
- **技术过程文件不上传网盘**：任务过程记录、TRANSCRIPT.json等只是技术过程不是直接面向使用者的文档（验证默认不单独成文）
- **知识库内容必须先在本地完成并验证，再同步到飞书知识库**，禁止直接在飞书知识库中编辑内容（除非紧急修复）

### 4.3 工具使用

- **统一使用已有工具**：禁止重复创建或使用其他工具
  - 视频下载解密：`scripts/download_decrypt.js`
  - 视频压缩：`scripts/compress.sh`
  - 讲义OCR：`scripts/batch_ocr.sh`
  - 音频转写：`scripts/transcribe_pipeline.py`
  - 网盘上传：`scripts/baidu_upload.py`
  - 做题（单卷）：`scripts/cdp/api_do_paper.js`
  - 做题（批量）：`scripts/cdp/batch_redo_papers.js`
  - 冲刺模考：`scripts/cdp/do_sprint_paper.js`
- **OCR统一工具**：macOS Vision框架
- **浏览器操作**：使用Playwright附加到已登录Chrome（Extension模式），不新开窗口（新窗口没有登录状态）
- **下载方式**：使用后台下载（curl），不弹出Chrome下载确认框
- **Playwright CLI**：`open`命令不支持`--extension`选项，必须用`attach --extension=chrome`模式

### 4.4 窗口管理

- **iTerm**：任务完成后立即关闭，禁止累积，大任务必须通过iTerm运行（可实时查看进度）
- **Chrome TAB**：开始新任务前关闭无关TAB，视频下载完成后关闭播放TAB
- **大任务检查**：最大5分钟检查一次进度
- **Playwright连接**：操作前必须关闭不相关的tab页，连接失败时自动刷新Token

### 4.5 目录与命名

- **统一目录结构**：本地、网盘、知识库三者一致
- **命名规范**：遵循 `NAMING_CONVENTION.md`，所有本地文件和知识库节点统一使用中文命名
- **统一进 CPA 课程区**：所有课程一律放 `高顿/CPA/` 走完整流程，不再设「待整理」中转分区，也不再设「课程库」中间层（2026-09-12 起去掉课程库层，见 ADR-020；「待整理」2026-09-08 起废弃，原唯一占用课程会计基础必修经采样为正课精讲子集后删除）
- **目录结构**：
  ```
  高顿/
  └── CPA/
      ├── 通用做题思路解析.md  # CPA 层跨课共用一份
      └── <课程名>/
          ├── 原始资源/        # videos/NN_讲题/{video.mp4,transcript.md}
          │                    # notes/NN_模块/{讲义_*.pdf,讲义_*_OCR.md}
          └── 知识详解/        # NN_模块组/{官方知识点}.md（一篇4节）+ 课程全局篇
  # 运行时过程件不在课程目录内，统一在仓库 data/_workspace/（账号级 _account + 课程级 <profile>，
  # gitignore、不传网盘、收尾分层清理，见 ADR-016）；课程目录物理上只有上面两层。
  ```

### 4.6 项目管理

- **测试驱动原则**：每个新功能/新流程先做单样本测试，验证通过后再批量执行
- **缺陷分类**：按严重程度（致命/严重/一般/轻微）和优先级（高/中/低）分类
- **小问题顺手修复**：一般/轻微 + 低/中优先级，测试过程中直接修复
- **大问题讨论处理**：致命/严重 + 高优先级，记录后讨论处理
- **文档同步清单**：每次需求/流程/结构变更时，按清单同步更新相关文档
- **项目及文档维护检查**：阶段性使用或主动要求调用，确保新文档融入项目管理

### 4.7 知识库管理

- **知识库名称**：CPA备考知识库
- **知识库两阶段生成**：第一阶段初始生成（讲义+视频），第二阶段迭代更新（做题+用户笔记+解析）
- **知识库来源清单**：所有内容可追溯、可验证
- **知识库发展与重设计原则**：变更知识库时必须遵循，父节点内容同步更新
- **父节点是否生成内容**：AI根据情况决定，不问人，但确定后要统一风格
- **子节点更新后父节点也要同步内容**
- **节点标题统一规范**
